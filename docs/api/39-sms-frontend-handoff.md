# راهنمای بخش پیامک برای فرانت‌اند

[← فهرست بخش‌ها](README.md)

این فایل نقطهٔ شروع بخش پیامک است. مرجع کامل روت‌ها و خروجی‌ها [38-sms-panel.md](38-sms-panel.md) است؛ اگر با ابزار هوش مصنوعی کار می‌کنید،
**اول همین فایل و بعد فایل ۳۸ و [01-general-conventions.md](01-general-conventions.md)** را بدهید.

## ۱. مدل کلی

- هر شرکت یک **سامانهٔ پیامک** دارد (مدیر آن را فعال می‌کند) و یک **کیف پول**. هر کاربر با **کلید دسترسی خودش** پیامک می‌فرستد.
- پیامک‌ها سه جا فرستاده می‌شوند: **بعد از ساخت بارنامه** (فرستنده، گیرنده و رانندگان همان بارنامه)، **ارسال گروهی به رانندگان یک مسیر**، و هیچ جای دیگر.
- متن پیامک بارنامه از **قالب** می‌آید. قالب‌ها سه‌تا هستند، برای هر شرکت و هر طرف یکی: `sender` (فرستنده)، `receiver` (گیرنده)، `driver` (راننده).
- متن ارسال گروهی را **خود کاربر** می‌نویسد و کلید قالب در آن جایگزین **نمی‌شود**.

## ۲. قالب و کلیدها (مهم)

قالب یک متن معمولی است که جاهای متغیر آن با آکولاد نوشته شده، مثلاً:

```
سلام راننده {driver_full_name} عزیز، بیجک {bijak_number} در تاریخ {issued_at} از {origin_city} به {destination_city} صادر شد.
```

هنگام ارسال، **سرور** هر `{کلید}` را با مقدار واقعی همان بارنامه عوض می‌کند. فرانت هرگز مقدارها را جایگزین نمی‌کند و متن نهایی را نمی‌فرستد؛
فقط شماره‌های گیرنده را می‌فرستد.

### گرفتن کلیدها

فرانت کلیدها را در کد ثابت نمی‌نویسد. با `GET /api/user/sms-templates/placeholders` لیست را بگیرید (مجوز `user.sms-templates.placeholders`):

```json
[
  { "key": "driver_full_name", "token": "{driver_full_name}", "label": "نام راننده" }
]
```

- `label` را روی دکمه یا چیپ نشان دهید.
- با کلیک، **`token`** (با آکولاد) را در جای مکان‌نمای ویرایشگر قالب بگذارید.
- کلید جدیدی که سرور اضافه کند خودکار در همین لیست می‌آید.

| `key`                | معنی           |
|----------------------|----------------|
| `bijak_number`       | شماره بیجک      |
| `tracking_code`      | کد رهگیری بیجک  |
| `referral_number`    | شماره حواله     |
| `issued_at`          | تاریخ صدور (شمسی، مانند `1405/08/19`) |
| `sender_full_name`   | نام فرستنده     |
| `receiver_full_name` | نام گیرنده      |
| `driver_full_name`   | نام راننده      |
| `origin_city`        | شهر مبدأ        |
| `destination_city`   | شهر مقصد        |
| `company_name`       | نام شرکت        |

### ذخیرهٔ قالب

- `GET /api/user/sms-templates` — قالب‌های تعریف‌شده (ممکن است کمتر از سه‌تا باشد).
- `PUT /api/user/sms-templates/{party}` با بدنهٔ `{ "body": "..." }` — ثبت یا ویرایش. `body` اجباری و حداکثر ۱۰۰۰ نویسه است.
- `DELETE /api/user/sms-templates/{party}` — حذف؛ اگر قالبی نباشد `404`.
- کلیدی که در لیست بالا نیست (مثلاً `{foo}`) در `PUT` خطای `422` می‌دهد و نام کلیدها در متن خطاست. آکولادی که کلید نیست هم همین‌طور.
- پیشنهاد: پیش‌نمایش بدهید ولی فقط برای نمایش؛ مثلاً هر `{کلید}` را با برچسب فارسی‌اش نشان دهید.

## ۳. دیالوگ پیامک بعد از ساخت بارنامه

1. بعد از پاسخ `201` ساخت بارنامه، `GET /api/user/waybills/{id}/sms` را صدا بزنید (مجوز `user.waybills.sms.show`).
   اگر `403` بود یا `data.available` برابر `false` بود دیالوگ را نشان ندهید (علت در `data.reason`).
2. برای هر عضو `data.parties` (همیشه سه طرف) یک بخش بسازید. هر شمارهٔ `recipients` یک چک‌باکس است؛ `name` را کنارش نشان دهید.
   - اگر `has_template` برابر `false` بود، بخش را غیرفعال کنید و کاربر را به تعریف قالب راهنمایی کنید (یا ارسال به آن طرف را ندهید).
3. با دکمهٔ ارسال: `POST /api/user/waybills/{id}/sms` (مجوز `user.waybills.sms.store`):

```json
{ "recipients": { "sender": ["09121234567"], "driver": ["09131234567", "09141234567"] } }
```

- فقط طرف‌هایی که حداقل یک شمارهٔ تیک‌خورده دارند را بفرستید. شماره را همان‌طور که از دیالوگ آمده بفرستید.
- کاربر می‌تواند شمارهٔ دستی هم اضافه کند (حداکثر ۵۰ شماره برای هر طرف، موبایل ایران). شمارهٔ غیرموبایل `422` می‌دهد.

### ارسال به چند راننده

رانندگان بارنامه (اول، دوم و حواله) در `recipients` طرف `driver` می‌آیند و کاربر می‌تواند **هر تعداد** از آن‌ها را تیک بزند. سرور متن را
**برای هر راننده جدا** می‌سازد:

- `{driver_full_name}` در پیام هر شماره، نام **همان راننده** است. اگر کاربر راننده اول و دوم را تیک بزند، هر کدام پیامی با نام خودشان می‌گیرند.
- بقیهٔ کلیدها برای همه یکی است.
- **شمارهٔ دستی برای راننده:** اگر قالب راننده `{driver_full_name}` دارد و کاربر شماره‌ای بنویسد که راننده‌ٔ این بارنامه نیست، سرور نام او را ندارد و `422` می‌دهد؛ هیچ پیامی فرستاده نمی‌شود.
  بنابراین:
  - اگر قالب راننده `{driver_full_name}` دارد، **افزودن شمارهٔ دستی برای طرف راننده را غیرفعال کنید** یا هشدار بدهید که پیام با نام نمی‌تواند برای شمارهٔ دلخواه فرستاده شود.
  - اگر قالب این کلید را ندارد، شمارهٔ دستی آزاد است. (فرانت می‌تواند با دیدن `{driver_full_name}` در `body` قالب راننده از `GET /api/user/sms-templates` این را تشخیص دهد.)
- یک شماره‌ای که زیر چند طرف آمده فقط یک پیام می‌گیرد (اولین طرف به ترتیب فرستنده، گیرنده، راننده).

### خواندن پاسخ ارسال

پاسخ `200` یک **آرایه** است؛ هر ردیف یک پیام است:

```json
[
  { "party": "sender", "success": true,  "phones": ["09121234567"], "tracking_code": "T1", "wallet_balance": 9990350, "message": "پیامک با موفقیت ارسال شد." },
  { "party": "driver", "success": true,  "phones": ["09131234567"], "tracking_code": "T2", "wallet_balance": 9990340, "message": "پیامک با موفقیت ارسال شد." },
  { "party": "driver", "success": false, "phones": ["09141234567"], "tracking_code": null, "wallet_balance": null, "message": "ارتباط با سامانه پیامک ناموفق بود. لطفا دوباره تلاش کنید." }
]
```

- **یک طرف ممکن است چند ردیف داشته باشد.** وقتی قالب راننده `{driver_full_name}` دارد، به‌ازای هر راننده یک ردیف می‌آید. وقتی ندارد، همهٔ رانندگان در یک ردیف‌اند.
  ردیف‌ها را با `phones` به شماره‌های انتخاب‌شده وصل کنید، نه با ترتیب یا تعداد.
- `success` هر ردیف را جدا بررسی کنید. اگر بعضی ناموفق بودند، فقط شماره‌های همان ردیف‌ها را به کاربر نشان بدهید تا دوباره تلاش کند.
- پاسخ `502` یعنی **همهٔ** ردیف‌ها ناموفق بوده‌اند.
- `wallet_balance` اگر عدد بود، موجودی نمایش‌داده‌شده را عوض کنید. `null` یعنی تغییری نکرده. آخرین مقدار غیر `null` موجودی نهایی است.

### خطاهای ۴۲۲ (متن در `errors.error[0]`)

همهٔ این‌ها قبل از اولین پیام بررسی می‌شوند؛ با هر کدام، هیچ پیامی فرستاده نمی‌شود:

| علت                                                         | کاری که فرانت بکند                                  |
|-------------------------------------------------------------|-----------------------------------------------------|
| سامانه فعال نیست / کلید کاربر ثبت نشده                      | کاربر را به صفحهٔ سامانهٔ پیامک ببرید                |
| بارنامه ابطال شده                                           | ارسال ممکن نیست                                      |
| قالب یک طرف تعریف نشده                                      | به تعریف قالب هدایت کنید                             |
| بارنامه مقدار یکی از کلیدهای قالب را ندارد (مثلاً شهر مبدأ خالی) | متن خطا نام طرف و کلیدها را دارد؛ به کاربر نشان دهید |
| شمارهٔ دستی راننده با قالب دارای `{driver_full_name}`        | همان ردیف بالا                                       |
| شمارهٔ نامعتبر                                              | خطا به‌ازای فیلد در `errors`                          |

## ۴. ارسال گروهی به رانندگان یک مسیر

1. `GET /api/user/sms-panel/driver-broadcast/drivers` با فیلترهای `origin_city_code`، `destination_city_code`، `date_from`، `date_to`
   (تاریخ میلادی `YYYY-MM-DD`) — لیست رانندگان برای بررسی.
2. کاربر متن را می‌نویسد و شماره‌هایی را که نمی‌خواهد برمی‌دارد.
3. `POST /api/user/sms-panel/driver-broadcast` با همان فیلترها به‌علاوهٔ `text` و `excluded_phones`.

> **توجه:** در این ارسال متن **همان‌طور که نوشته شده** برای همه می‌رود و کلید قالب (مثل `{driver_full_name}`) جایگزین **نمی‌شود**.
> اگر کاربر آکولاد بنویسد، همان نویسه‌ها در پیامک ظاهر می‌شود. در این صفحه دکمهٔ «درج کلید» نگذارید. (اگر نیاز به نام راننده در ارسال گروهی دارید،
> باید در بک‌اند اضافه شود.)

## ۵. صفحهٔ سامانه و کیف پول

- `GET /api/user/sms-panel` — `is_active`، `token_status` (`registered` / `not_registered`)، `wallet_balance`.
  اگر `is_active` برابر `false` بود، دکمهٔ «ساخت سامانه» (`POST /api/user/sms-panel/register`) را فقط برای کسی نشان دهید که مجوز `user.sms-panel.register` دارد.
- اگر `token_status` برابر `not_registered` بود، فرم ثبت کلید (`PUT /api/user/sms-panel/token` با `{ "api_key": "..." }`) را نشان دهید.
- `POST /api/user/sms-panel/wallet/refresh` — به‌روزرسانی دستی موجودی.

## ۶. مجوزها

| مجوز                                    | کاربرد                      |
|-----------------------------------------|-----------------------------|
| `user.sms-panel.show`، `.token.update`، `.wallet.refresh` | پیش‌فرض برای هر کاربر شرکت |
| `user.sms-panel.register`               | ساخت سامانه                  |
| `user.sms-panel.driver-broadcast.drivers` / `.send` | ارسال گروهی           |
| `user.sms-templates.index` / `.placeholders` / `.update` / `.destroy` | قالب‌ها |
| `user.waybills.sms.show` / `.store`     | دیالوگ و ارسال پیامک بارنامه |

دکمه یا صفحه‌ای را که کاربر مجوزش را ندارد پنهان کنید. نقش `demo` فقط خواندنی است (ارسال و ویرایش قالب را ندارد).

## ۷. چک‌لیست کار فرانت

- [ ] ویرایشگر قالب با دکمه‌های کلید از `placeholders` (درج `token`).
- [ ] دیالوگ بعد از ساخت بارنامه با چک‌باکس هر شماره، شامل چند راننده.
- [ ] خواندن پاسخ ارسال به‌صورت **آرایهٔ ردیف‌ها**، با تطبیق از روی `phones`.
- [ ] غیرفعال کردن شمارهٔ دستی برای راننده وقتی قالب راننده `{driver_full_name}` دارد.
- [ ] نمایش خطاهای ۴۲۲ و ۵۰۲ و به‌روزرسانی موجودی کیف پول بعد از هر ارسال.
- [ ] صفحهٔ ارسال گروهی بدون دکمهٔ درج کلید.
