# فیلدهای اضافی

[← فهرست بخش‌ها](README.md)

**پنل:** پنل شرکت — **تعداد روت:** ۳

هر شرکت دقیقاً **شش فیلد اضافی** دارد که روی بارنامه نمایش داده می‌شوند و مقدارشان را کاربر هنگام ثبت بارنامه پر می‌کند.
شش فیلد همراه ساخته شدن شرکت ساخته می‌شوند (با عنوان‌های اول تا ششم، مخفی و از نوع متن)؛ پس **ایجاد و حذف ندارند** و
فقط می‌شود تنظیماتشان را خواند و ویرایش کرد.

### ۳۲.۱ روت‌ها و مجوزها

| #    | متد        | مسیر                                      | نوع ورودی | مجوز لازم                              | کاربرد                 |
|------|------------|-------------------------------------------|-----------|----------------------------------------|------------------------|
| ۳۲.۱ | GET        | `/api/user/shared-additional-fields`      | ندارد     | `user.shared-additional-fields.index`  | فهرست شش فیلد          |
| ۳۲.۲ | GET        | `/api/user/shared-additional-fields/{id}` | ندارد     | `user.shared-additional-fields.show`   | یک فیلد                |
| ۳۲.۳ | PUT\|PATCH | `/api/user/shared-additional-fields/{id}` | JSON      | `user.shared-additional-fields.update` | ویرایش تنظیمات یک فیلد |

`{id}` شناسهٔ ردیف فیلد است (`id` در پاسخ)، نه `number`. شناسهٔ فیلد شرکت دیگر `404` می‌دهد.

### ۳۲.۲ شکل یک فیلد (خروجی)

```json
{
  "id": 12,
  "number": 1,
  "title": "شمارهٔ پلمب",
  "is_visible": true,
  "is_visible_in_print": false,
  "field_type": "text",
  "length": 20,
  "layout": "rtl",
  "default_value": null,
  "description": "فقط برای بارهای صادراتی",
  "waybill_column": "additional_field_1"
}
```

| فیلد                  | نوع              | توضیح                                                              |
|-----------------------|------------------|--------------------------------------------------------------------|
| `id`                  | int              | شناسهٔ ردیف؛ در آدرس `show` و `update` می‌آید                        |
| `number`              | int (۱ تا ۶)     | شمارهٔ ثابت فیلد؛ تغییر نمی‌کند و کلید مقدار در بارنامه است           |
| `title`               | string           | عنوانی که کنار فیلد نمایش داده می‌شود                               |
| `is_visible`          | bool             | آیا فیلد در فرم بارنامه نمایش داده شود (پیش‌فرض `false`)              |
| `is_visible_in_print` | bool             | آیا فیلد در چاپ بارنامه بیاید (پیش‌فرض `false`)                      |
| `field_type`          | string (enum)    | نوع ورودی؛ مقادیر در [۳۲.۵](#۳۲۵-نوع-و-جهت-فیلد)                     |
| `length`              | int (۱ تا ۶۵۵۳۵) | طول فیلد برای نمایش (پیش‌فرض `1`)                                   |
| `layout`              | string (enum)    | جهت متن: `rtl` یا `ltr` (پیش‌فرض `rtl`)                             |
| `default_value`       | string\|null     | مقدار پیش‌فرضی که فرم از ابتدا پر می‌کند                            |
| `description`         | string\|null     | توضیح یا راهنمای فیلد                                               |
| `waybill_column`      | string           | نام ستون مقدار در بارنامه: `additional_field_<number>`              |

### ۳۲.۳ فهرست و یک فیلد

**`GET /api/user/shared-additional-fields`** — بدون ورودی. همیشه هر شش فیلد را، بدون صفحه‌بندی و به ترتیب `number`، برمی‌گرداند:

```json
{ "success": true, "message": "عملیات موفق بود", "data": [ { "id": 12, "number": 1, "...": "..." } ] }
```

**`GET /api/user/shared-additional-fields/{id}`** — همان شکل بالا، به‌صورت یک شیء در `data`.

### ۳۲.۴ ویرایش — `PUT|PATCH /api/user/shared-additional-fields/{id}`

بدنهٔ JSON. همهٔ کلیدها اختیاری‌اند؛ کلیدی که نفرستید مقدار ذخیره‌شده‌اش را نگه می‌دارد. `number` و `company_id` را نمی‌شود عوض کرد
(اگر بفرستید نادیده گرفته می‌شود).

| ورودی                 | قاعده                               |
|-----------------------|-------------------------------------|
| `title`               | رشته، حداکثر ۲۵۵ نویسه، خالی نباشد   |
| `is_visible`          | بولی                                |
| `is_visible_in_print` | بولی                                |
| `field_type`          | یکی از مقادیر جدول ۳۲.۵             |
| `length`              | عدد صحیح ۱ تا ۶۵۵۳۵                 |
| `layout`              | `rtl` یا `ltr`                      |
| `default_value`       | رشته یا `null` (برای پاک کردن)       |
| `description`         | رشته یا `null` (برای پاک کردن)       |

مثال:

```json
{ "title": "شمارهٔ پلمب", "is_visible": true, "is_visible_in_print": true, "field_type": "text", "length": 20, "layout": "ltr" }
```

**خروجی (`200`):** پیام فارسی ویرایش موفق و فیلد به‌روز‌شده (همان شکل ۳۲.۲) در `data`. خطای اعتبارسنجی `422` است
(قالب در [بخش ۱](01-general-conventions.md)).

### ۳۲.۵ نوع و جهت فیلد

| `field_type` | معنی             | مقدار قابل قبول هنگام ثبت بارنامه |
|--------------|------------------|------------------------------------|
| `text`       | متن کوتاه        | رشته                               |
| `long_text`  | متن بلند         | رشته                               |
| `number`     | عدد              | عدد                                |
| `date`       | تاریخ            | تاریخ معتبر (`YYYY-MM-DD`)          |
| `date_time`  | تاریخ و ساعت     | تاریخ معتبر                         |
| `time`       | ساعت             | `HH:mm` یا `HH:mm:ss`              |
| `checkbox`   | تیک              | بولی                               |
| `email`      | ایمیل            | ایمیل معتبر                         |
| `url`        | آدرس وب          | URL معتبر                           |

`layout`: `rtl` (راست‌به‌چپ) یا `ltr` (چپ‌به‌راست).

### ۳۲.۶ مقدار فیلدها در بارنامه

- **ثبت و ویرایش بارنامه:** مقدارها را در کلید `additional_fields` بفرستید، با **شمارهٔ فیلد** (`1` تا `6`) به‌عنوان کلید.
  کلید دیگری `422` می‌دهد. هر مقدار اختیاری و nullable است و با `field_type` همان فیلد اعتبارسنجی می‌شود (جدول بالا):

  ```json
  { "additional_fields": { "1": "P-20481", "3": "2026-11-03", "5": null } }
  ```

- **خواندن بارنامه:** مقدارها در خود بارنامه با نام `additional_field_1` تا `additional_field_6` می‌آیند (همان `waybill_column`).
- **گزارش‌ساز:** همین ستون‌ها در گزارش‌ها قابل انتخاب‌اند ([بخش ۲۸](28-report-builder.md)).

### ۳۲.۷ نکات برای فرانت‌اند

- `is_visible`، `is_visible_in_print`، `length`، `layout` و `default_value` را **فرانت‌اند** به کار می‌گیرد (نمایش در فرم و چاپ، عرض، جهت،
  پر کردن اولیه)؛ سرور هنگام ثبت بارنامه فقط **نوع مقدار** را بر پایهٔ `field_type` می‌سنجد و طول، پنهان‌بودن یا مقدار پیش‌فرض را اعمال نمی‌کند.
- فقط فیلدهایی را که `is_visible` آن‌ها `true` است در فرم بارنامه نشان دهید.
- بعد از تغییر `field_type`، مقدارهای قبلاً ذخیره‌شده دوباره بررسی نمی‌شوند؛ فقط مقدارهای جدید با نوع تازه سنجیده می‌شوند.
