# سامانه پیامک

[← فهرست بخش‌ها](README.md)

**پنل:** پنل شرکت (به‌همراه دو تنظیم در پنل ادمین) — **تعداد روت:** ۱۲

هر شرکت ابتدا سامانهٔ پیامک خود را می‌سازد و فعال می‌کند. بعد از آن هر کاربر با **کلید دسترسی خودش** پیامک می‌فرستد و موجودی کیف پول
شرکت در همین بخش نمایش داده می‌شود. هر شماره در یک ارسال فقط یک پیام می‌گیرد.

### ۳۸.۱ روت‌ها و مجوزها

| #      | متد    | مسیر                                                | نوع ورودی    | مجوز لازم                                 | کاربرد                                 |
|--------|--------|-----------------------------------------------------|--------------|-------------------------------------------|----------------------------------------|
| ۳۸.۱   | GET    | `/api/user/sms-panel`                               | ندارد        | `user.sms-panel.show`                     | وضعیت سامانه، کلید کاربر و موجودی       |
| ۳۸.۲   | POST   | `/api/user/sms-panel/register`                      | ندارد        | `user.sms-panel.register`                 | ساخت و فعال‌سازی سامانه (دسترسی روت)    |
| ۳۸.۳   | PUT    | `/api/user/sms-panel/token`                         | JSON         | `user.sms-panel.token.update`             | ثبت یا تغییر کلید خود کاربر             |
| ۳۸.۴   | POST   | `/api/user/sms-panel/wallet/refresh`                | ندارد        | `user.sms-panel.wallet.refresh`           | گرفتن موجودی تازهٔ کیف پول               |
| ۳۸.۵   | GET    | `/api/user/sms-templates`                           | ندارد        | `user.sms-templates.index`                | قالب‌های تعریف‌شده                       |
| ۳۸.۶   | GET    | `/api/user/sms-templates/placeholders`              | ندارد        | `user.sms-templates.placeholders`         | کلیدهای قابل استفاده در قالب            |
| ۳۸.۷   | PUT    | `/api/user/sms-templates/{party}`                   | JSON         | `user.sms-templates.update`               | ثبت یا ویرایش قالب یک طرف               |
| ۳۸.۸   | DELETE | `/api/user/sms-templates/{party}`                   | ندارد        | `user.sms-templates.destroy`              | حذف قالب یک طرف                         |
| ۳۸.۹   | GET    | `/api/user/waybills/{waybill}/sms`                  | ندارد        | `user.waybills.sms.show`                  | دادهٔ دیالوگ ارسال پیامک بارنامه         |
| ۳۸.۱۰  | POST   | `/api/user/waybills/{waybill}/sms`                  | JSON         | `user.waybills.sms.store`                 | ارسال پیامک بارنامه                     |
| ۳۸.۱۱  | GET    | `/api/user/sms-panel/driver-broadcast/drivers`      | query string | `user.sms-panel.driver-broadcast.drivers` | لیست رانندگان یک مسیر برای بررسی        |
| ۳۸.۱۲  | POST   | `/api/user/sms-panel/driver-broadcast`              | JSON         | `user.sms-panel.driver-broadcast.send`    | ارسال متن به رانندگان یک مسیر           |

- `{party}` یکی از `sender`، `receiver` و `driver` است؛ مقدار دیگر `404` می‌دهد.
- **دسترسی‌های پیش‌فرض** (هر کاربر شرکت دارد): `show`، `token.update` و `wallet.refresh`.
- **دسترسی‌هایی که مدیر باید بدهد:** `user.sms-panel.register`، `user.sms-panel.driver-broadcast.*`، `user.sms-templates.*` و
  `user.waybills.sms.*`. نقش `companyManager` همهٔ آن‌ها را دارد.
- نقش `demo` این‌ها را ندارد: `register`، `token.update`، `driver-broadcast.send`، `sms-templates.update`، `sms-templates.destroy` و `waybills.sms.store`.

### ۳۸.۲ قالب پاسخ و خطاها

پاسخ موفق همان قالب عمومی است ([بخش ۱](01-general-conventions.md)) و در مثال‌های این بخش فقط مقدار `data` آمده است. خطاهای سرویس این شکل را دارند
و متن خطا برای نمایش به کاربر در `errors.error[0]` است:

```json
{ "success": false, "message": "خطایی رخ داده است", "errors": { "error": ["کلید دسترسی سامانه پیامک ثبت نشده است."] } }
```

خطاهای مشترک:

| کد    | متن خطا                                                   | علت                                                     |
|-------|-----------------------------------------------------------|---------------------------------------------------------|
| `403` | شما به این صفحه دسترسی ندارید                              | کاربر مجوز این مسیر را ندارد                            |
| `422` | سامانه پیامک برای این شرکت فعال نشده است.                  | سامانهٔ شرکت هنوز ساخته نشده                             |
| `422` | کلید دسترسی سامانه پیامک ثبت نشده است.                     | کاربر کلید خودش را ثبت نکرده                            |
| `502` | ارتباط با سامانه پیامک ناموفق بود. لطفا دوباره تلاش کنید.  | سامانهٔ پیامک خطا داده، پاسخ نداده یا تنظیم سرور کامل نیست |
| `503` | سایت در حال به‌روزرسانی است. لطفا کمی بعد دوباره مراجعه کنید. | سایت در حالت تعمیر است ([۳۸.۹](#۳۸۹-تنظیمات-ادمین))     |

### ۳۸.۳ سامانه و کلید کاربر

#### وضعیت — `GET /api/user/sms-panel`

```json
{
  "is_active": true,
  "activated_at": "2026-11-10T08:00:00.000000Z",
  "token_status": "registered",
  "wallet_balance": 9990350,
  "wallet_updated_at": "2026-11-10T09:30:00.000000Z"
}
```

| فیلد                | نوع           | توضیح                                                                 |
|---------------------|---------------|-----------------------------------------------------------------------|
| `is_active`         | bool          | آیا سامانهٔ شرکت فعال است                                              |
| `activated_at`      | datetime\|null | زمان فعال‌سازی                                                        |
| `token_status`      | string        | وضعیت کلید **همین کاربر**: `registered` یا `not_registered`            |
| `wallet_balance`    | number\|null  | موجودی ذخیره‌شدهٔ کیف پول شرکت ([۳۸.۴](#۳۸۴-کیف-پول))                  |
| `wallet_updated_at` | datetime\|null | زمان آخرین به‌روزرسانی موجودی                                         |

خود کلید هیچ‌وقت در پاسخ نمی‌آید. اگر سامانه هنوز ساخته نشده باشد، `is_active` برابر `false` و بقیهٔ فیلدها `null` یا `not_registered` هستند.
روت‌های ثبت‌نام، ثبت کلید و به‌روزرسانی کیف پول هم همین شکل را برمی‌گردانند.

#### ساخت و فعال‌سازی — `POST /api/user/sms-panel/register`

بدون ورودی. فقط کاربری که مجوز `user.sms-panel.register` دارد می‌تواند این روت را صدا بزند. درخواست به سامانهٔ پیامک فرستاده می‌شود، سامانهٔ
شرکت فعال می‌شود، کلید برگشتی برای **همین کاربر** ذخیره می‌شود و موجودی اولیهٔ کیف پول ثبت می‌شود.

| دادهٔ ارسالی به سامانه                                                    | منبع               |
|--------------------------------------------------------------------------|--------------------|
| `phone`، `first_name`، `last_name`، `email`، `address`، `national_id`     | کاربر ثبت‌کننده     |
| `company_name`، `company_phone`، `company_email`، `company_address`، `company_national_id` | اطلاعات شرکت       |
| `type`                                                                   | تنظیم سرور         |

**خروجی (`201`):** شکل وضعیت بالا.

| کد    | علت                                                                       |
|-------|---------------------------------------------------------------------------|
| `422` | سامانهٔ این شرکت قبلا فعال شده است                                         |
| `422` | کاربر شماره موبایل معتبر در پروفایل ندارد                                  |
| `422` | سامانهٔ پیامک داده‌ها را نپذیرفته؛ خطاها به‌ازای هر فیلد در `errors` می‌آیند |
| `502` | خطا در ارتباط با سامانه یا نبودن کلید در پاسخ؛ چیزی ذخیره نمی‌شود          |

```json
{ "success": false, "message": "خطا", "errors": { "phone": ["شماره معتبر نیست"] } }
```

#### ثبت یا تغییر کلید — `PUT /api/user/sms-panel/token`

```json
{ "api_key": "..." }
```

`api_key` اجباری و حداکثر ۵۰۰ نویسه است. کاربر فقط کلید خودش را ثبت می‌کند و هر زمان می‌تواند آن را عوض کند. پیش از فعال بودن سامانه `422` می‌دهد.
**خروجی (`200`):** شکل وضعیت بالا با `token_status: "registered"`.

### ۳۸.۴ کیف پول

هر شرکت یک کیف پول در سامانهٔ پیامک دارد و آخرین موجودی آن در سامانهٔ ما ذخیره می‌شود. برای نمایش موجودی از `wallet_balance` در
`GET /api/user/sms-panel` استفاده کنید؛ این روت با سامانهٔ پیامک تماس نمی‌گیرد.

| زمان به‌روزرسانی                       | منبع مقدار                         |
|----------------------------------------|------------------------------------|
| فعال‌سازی سامانه                        | کیف پول برگشتی در پاسخ ثبت‌نام      |
| به‌روزرسانی دستی (روت زیر)              | موجودی فعلی از سامانهٔ پیامک         |
| بعد از هر ارسال موفق پیامک              | موجودی برگشتی همراه همان ارسال      |

#### به‌روزرسانی دستی — `POST /api/user/sms-panel/wallet/refresh`

بدون ورودی. موجودی با **کلید خود کاربر** از سامانهٔ پیامک گرفته و ذخیره می‌شود.

**خروجی (`200`):**

```json
{
  "is_active": true,
  "activated_at": "2026-11-10T08:00:00.000000Z",
  "token_status": "registered",
  "wallet_balance": 2500.5,
  "wallet_updated_at": "2026-11-10T10:15:00.000000Z"
}
```

| کد    | علت                                                                  |
|-------|----------------------------------------------------------------------|
| `422` | سامانه فعال نیست یا کاربر کلید ثبت نکرده است                          |
| `502` | سامانهٔ پیامک خطا داده یا موجودی در پاسخ نیست؛ موجودی قبلی تغییر نمی‌کند |

#### موجودی بعد از ارسال

پاسخ ارسال پیامک بارنامه و ارسال گروهی فیلد `wallet_balance` دارد و همان مقدار در سرور هم ذخیره شده است.

- اگر مقدار عدد بود، عدد نمایش‌داده‌شده را با آن عوض کنید.
- `null` یعنی این ارسال موجودی برنگرداند یا ناموفق بود؛ موجودی ذخیره‌شده تغییر نکرده است و عدد قبلی را نگه دارید.
- ارسال بارنامه برای هر ردیف پاسخ جدا انجام می‌شود (هر طرف، و برای رانندگان هر متن متفاوت)، پس آخرین مقدار غیر `null` در آرایهٔ پاسخ موجودی نهایی است.

موجودی به‌ازای **شرکت** نگه‌داری می‌شود و عددی است که سامانهٔ پیامک برگردانده (با دو رقم اعشار ذخیره می‌شود). آخرین ارسال یا به‌روزرسانی، مقدار را برای همهٔ کاربران شرکت تعیین می‌کند.

### ۳۸.۵ قالب‌ها

برای هر شرکت و هر طرف (`sender`، `receiver`، `driver`) یک قالب وجود دارد.

#### فهرست — `GET /api/user/sms-templates`

فقط قالب‌های تعریف‌شده را برمی‌گرداند:

```json
[
  {
    "id": 3,
    "party": "driver",
    "party_label": "راننده",
    "body": "راننده گرامی {driver_full_name}، بیجک {bijak_number} صادر شد.",
    "updated_at": "2026-11-10T08:00:00.000000Z"
  }
]
```

#### کلیدها — `GET /api/user/sms-templates/placeholders`

```json
[
  { "key": "bijak_number", "token": "{bijak_number}", "label": "شماره بیجک" }
]
```

| `key`                | معنی            | مقدار                                                  |
|----------------------|-----------------|--------------------------------------------------------|
| `bijak_number`       | شماره بیجک      | شماره بیجک بارنامه                                     |
| `tracking_code`      | کد رهگیری بیجک  | کد رهگیری بارنامه                                      |
| `referral_number`    | شماره حواله     | شماره حوالهٔ بارنامه                                    |
| `issued_at`          | تاریخ صدور      | تاریخ شمسی مانند `1405/08/19`                          |
| `sender_full_name`   | نام فرستنده     | نام ثبت‌شده در بارنامه                                  |
| `receiver_full_name` | نام گیرنده      | نام ثبت‌شده در بارنامه                                  |
| `driver_full_name`   | نام راننده      | در پیام **طرف راننده**: نام همان رانندهٔ گیرندهٔ پیام. در پیام فرستنده و گیرنده: رانندهٔ اول، در نبود آن رانندهٔ حواله و سپس رانندهٔ دوم |
| `origin_city`        | شهر مبدأ        | شهر آدرس فرستنده در بارنامه                             |
| `destination_city`   | شهر مقصد        | شهر آدرس گیرنده در بارنامه                              |
| `company_name`       | نام شرکت        | نام شرکت جاری                                          |

#### ثبت یا ویرایش — `PUT /api/user/sms-templates/{party}`

```json
{ "body": "راننده گرامی {driver_full_name}، بیجک {bijak_number} از {origin_city} به {destination_city} صادر شد." }
```

`body` اجباری و حداکثر ۱۰۰۰ نویسه است. کلید ناشناخته در متن `422` می‌دهد. **خروجی (`200`):** همان شکل یک قالب.

#### حذف — `DELETE /api/user/sms-templates/{party}`

**خروجی (`200`):** پیام موفق با `data` خالی. اگر قالبی برای آن طرف نباشد `404` می‌دهد.

### ۳۸.۶ پیامک بارنامه

#### دادهٔ دیالوگ — `GET /api/user/waybills/{waybill}/sms`

```json
{
  "available": true,
  "reason": null,
  "parties": [
    {
      "party": "sender",
      "label": "فرستنده",
      "has_template": true,
      "recipients": [{ "phone": "09121234567", "name": "فرستنده نمونه" }]
    },
    { "party": "receiver", "label": "گیرنده", "has_template": false, "recipients": [] },
    {
      "party": "driver",
      "label": "راننده",
      "has_template": true,
      "recipients": [
        { "phone": "09131234567", "name": "راننده اول" },
        { "phone": "09141234567", "name": "راننده دوم" }
      ]
    }
  ]
}
```

- `parties` همیشه هر سه طرف را دارد. برای راننده، رانندهٔ اول، دوم و حواله در صورت وجود می‌آیند.
- فقط شماره‌های موبایل معتبر می‌آیند و تکراری‌ها حذف می‌شوند.
- `available` برابر `false` یعنی کاربر فعلا نمی‌تواند بفرستد و علت در `reason` است: سامانه فعال نیست، کلید ثبت نشده یا بارنامه ابطال شده است.
- بارنامه‌ای که کاربر اجازهٔ دیدنش را ندارد `404` می‌دهد.

#### ارسال — `POST /api/user/waybills/{waybill}/sms`

```json
{ "recipients": { "sender": ["09121234567"], "receiver": [], "driver": ["09131234567", "09150000000"] } }
```

| ورودی                 | قاعده                                                                                  |
|-----------------------|----------------------------------------------------------------------------------------|
| `recipients`          | اجباری؛ شیء با حداقل یکی از کلیدهای `sender`، `receiver`، `driver`                       |
| `recipients.<party>`  | آرایه، حداکثر ۵۰ شماره؛ شامل شماره‌های تیک‌خورده و شماره‌هایی که کاربر اضافه کرده         |
| `recipients.<party>.*`| موبایل ایران: `09…`، `9…`، `+989…`، `989…` یا `00989…`؛ ارقام فارسی و عربی هم پذیرفته می‌شود |

**خروجی (`200`):** برای هر طرفی که شماره دارد یک ردیف:

```json
[
  {
    "party": "sender",
    "success": true,
    "phones": ["09121234567"],
    "tracking_code": "SXSVfJLXe6bI0ZYt",
    "wallet_balance": 9990350,
    "message": "پیامک با موفقیت ارسال شد."
  },
  {
    "party": "driver",
    "success": false,
    "phones": ["09131234567", "09150000000"],
    "tracking_code": null,
    "wallet_balance": null,
    "message": "ارتباط با سامانه پیامک ناموفق بود. لطفا دوباره تلاش کنید."
  }
]
```

| کد    | علت                                                                                       |
|-------|-------------------------------------------------------------------------------------------|
| `422` | ورودی نامعتبر، مانند شماره‌ای که موبایل نیست (خطا در `errors` به‌ازای هر فیلد)               |
| `422` | سامانه فعال نیست، کلید ثبت نشده، بارنامه ابطال شده یا شماره‌ای برای ارسال نمانده           |
| `422` | برای طرفی که شماره دارد قالب تعریف نشده است؛ نام طرف‌ها در متن خطا می‌آید                  |
| `422` | این بارنامه مقدار یکی از کلیدهای قالب را ندارد؛ نام طرف و کلیدها در متن خطا می‌آید         |
| `502` | ارسال برای همهٔ طرف‌ها ناموفق بوده است                                                     |

- همهٔ بررسی‌ها پیش از اولین پیام انجام می‌شود؛ با هر خطای `422` هیچ پیامی فرستاده نمی‌شود.
- قالب فقط برای طرف‌هایی لازم است که در این ارسال شماره دارند.
- اگر ارسال یک ردیف ناموفق و ردیف دیگر موفق باشد، پاسخ `200` است؛ نتیجهٔ هر ردیف را با `success` بررسی کنید.
- شماره‌ای که زیر چند طرف آمده باشد فقط یک پیام می‌گیرد؛ پیام اولین طرف به ترتیب فرستنده، گیرنده، راننده.

#### ارسال به چند راننده

کاربر می‌تواند چند راننده از همین بارنامه را (رانندهٔ اول، دوم و حواله) انتخاب کند. متن **برای هر راننده جدا ساخته می‌شود**:

- کلید `{driver_full_name}` در پیام هر شماره، نام **همان رانندهٔ صاحب شماره** است، نه نام رانندهٔ اول. شماره‌ها را همان‌طور که دیالوگ داده (فیلد `phone` در `recipients` طرف `driver`) برگردانید تا سرور بتواند راننده را تشخیص دهد؛ فرمت شماره مهم نیست (`+98…` و ارقام فارسی هم شناخته می‌شود).
- بقیهٔ کلیدها (شمارهٔ بیجک، شهرها، تاریخ، نام شرکت و …) برای همهٔ رانندگان یکی است.
- **شمارهٔ دستی:** اگر کاربر شماره‌ای اضافه کند که به هیچ‌کدام از رانندگان این بارنامه تعلق ندارد و قالب راننده `{driver_full_name}` دارد، سرور نمی‌داند اسم او چیست و `422` می‌دهد (مقدار «نام راننده» را ندارد) و **هیچ پیامی فرستاده نمی‌شود**. اگر قالب این کلید را نداشته باشد، شمارهٔ دستی مشکلی ندارد.
- **شکل پاسخ:** شماره‌هایی که متن نهایی‌شان یکی است در **یک ردیف** و یک پیام می‌آیند. پس وقتی قالب راننده `{driver_full_name}` دارد، برای هر راننده یک ردیف با `party: "driver"` و یک شمارهٔ `phones` برمی‌گردد؛ وگرنه همهٔ رانندگان در یک ردیف هستند. ردیف‌های راننده را با `phones` به شمارهٔ انتخاب‌شده وصل کنید، نه با ترتیب.
- هر ردیف جدا به سامانهٔ پیامک می‌رود، پس ممکن است بعضی ردیف‌ها موفق و بعضی ناموفق باشند. فقط وقتی **همهٔ** ردیف‌ها ناموفق باشند `502` برمی‌گردد.

```json
{ "recipients": { "driver": ["09133333333", "09134444444"] } }
```

با قالب `راننده {driver_full_name} بیجک {bijak_number}` دو پیام فرستاده می‌شود: «راننده راننده اول بیجک 555» و «راننده راننده دوم بیجک 555»؛ پاسخ:

```json
[
  { "party": "driver", "success": true, "phones": ["09133333333"], "tracking_code": "T1", "wallet_balance": 9990350, "message": "پیامک با موفقیت ارسال شد." },
  { "party": "driver", "success": true, "phones": ["09134444444"], "tracking_code": "T2", "wallet_balance": 9990340, "message": "پیامک با موفقیت ارسال شد." }
]
```

### ۳۸.۷ ارسال گروهی به رانندگان یک مسیر

رانندگان بارنامه‌های **صادرشده** که کاربر اجازهٔ دیدنشان را دارد و تاریخ صدورشان در بازهٔ انتخابی است، از مبدأ به مقصد. رانندهٔ اول، دوم و حواله همه حساب می‌شوند.

#### لیست برای بررسی — `GET /api/user/sms-panel/driver-broadcast/drivers`

| ورودی                   | قاعده                                     |
|-------------------------|-------------------------------------------|
| `origin_city_code`      | اجباری؛ کد شهر موجود                      |
| `destination_city_code` | اجباری؛ کد شهر موجود                      |
| `date_from`             | اجباری؛ تاریخ میلادی `YYYY-MM-DD`         |
| `date_to`               | اجباری؛ تاریخ میلادی، برابر یا بعد از `date_from` |

هر دو روز ابتدا و انتهای بازه جزو نتیجه هستند.

```json
{
  "available": true,
  "reason": null,
  "drivers": [
    { "phone": "09131234567", "full_name": "راننده نمونه", "national_code": "1234567890", "trips_count": 3 }
  ],
  "without_valid_phone": 1
}
```

- هر شماره یک بار می‌آید و `trips_count` تعداد بارنامه‌های آن در این بازه است.
- `without_valid_phone` تعداد رانندگانی است که موبایل معتبر ندارند و پیامک نمی‌گیرند.
- لیست حتی وقتی `available` برابر `false` است برمی‌گردد تا کاربر بتواند آن را ببیند.

#### ارسال — `POST /api/user/sms-panel/driver-broadcast`

همان چهار فیلتر به‌همراه:

| ورودی               | قاعده                                                  |
|---------------------|--------------------------------------------------------|
| `text`              | اجباری؛ حداکثر ۱۰۰۰ نویسه؛ کلیدهای قالب در آن جایگزین نمی‌شوند |
| `excluded_phones`   | اختیاری؛ آرایهٔ شماره‌هایی که کاربر از لیست برداشته      |

```json
{
  "origin_city_code": 11320000,
  "destination_city_code": 21310000,
  "date_from": "2026-10-01",
  "date_to": "2026-10-31",
  "text": "بار جدید موجود است.",
  "excluded_phones": ["09135555555"]
}
```

لیست در سرور دوباره ساخته می‌شود، پس فقط رانندگان همین مسیر پیام می‌گیرند. پیام با کلید خود کاربر و برای هر شماره یک بار فرستاده می‌شود.

**خروجی (`200`):**

```json
{
  "success": true,
  "phones": ["09131234567", "09134444444"],
  "tracking_code": "SXSVfJLXe6bI0ZYt",
  "wallet_balance": 9956140,
  "message": "پیامک با موفقیت ارسال شد."
}
```

| کد    | علت                                                       |
|-------|-----------------------------------------------------------|
| `422` | ورودی نامعتبر، سامانه فعال نیست، کلید ثبت نشده یا راننده‌ای برای ارسال نمانده |
| `502` | ارسال ناموفق بوده است                                      |

### ۳۸.۸ نکات برای فرانت‌اند

- **صفحهٔ سامانه پیامک:** با `GET /api/user/sms-panel` وضعیت را بگیرید. اگر `is_active` برابر `false` بود، گزینهٔ «ساخت سامانه پیامک» را فقط به کاربری که مجوز `register` دارد نشان دهید. اگر `token_status` برابر `not_registered` بود، فرم ثبت کلید را نشان دهید.
- **موجودی:** `wallet_balance` را همراه دکمهٔ به‌روزرسانی (روت `wallet/refresh`) نمایش دهید و بعد از هر ارسال طبق [۳۸.۴](#۳۸۴-کیف-پول) عوض کنید.
- **بعد از ساخت بارنامه:** پس از پاسخ `201`، `GET /api/user/waybills/{id}/sms` را صدا بزنید. اگر `403` بود یا `available` برابر `false` بود دیالوگ را نشان ندهید.
- **دیالوگ بارنامه:** برای هر طرف چک‌باکس شماره‌ها و امکان افزودن شماره بسازید. اگر `has_template` طرفی `false` بود، کاربر را به تعریف قالب راهنمایی کنید.
- **ارسال گروهی:** ابتدا لیست را نشان دهید، شماره‌هایی را که کاربر برداشت در `excluded_phones` بفرستید.

### ۳۸.۹ تنظیمات ادمین

`GET` و `PUT|PATCH /api/admin/settings` با مجوزهای `admin.settings.show` و `admin.settings.update` این دو تنظیم را هم دارند:

```json
{ "sms": { "panel_url": "https://main.peykad.ir" }, "site": { "status": "maintenance" } }
```

| کلید            | قاعده                                                | پیش‌فرض             |
|-----------------|------------------------------------------------------|---------------------|
| `sms.panel_url` | آدرس `http` یا `https`، حداکثر ۲۵۵ نویسه             | مقدار `SMS_PANEL_URL` |
| `site.status`   | `active` یا `maintenance`                            | `active`            |

در حالت `maintenance` همهٔ روت‌های پنل شرکت و پنل بیمه `503` می‌دهند. روت‌های ورود و پنل ادمین باز می‌مانند تا ادمین بتواند سایت را دوباره فعال کند.

### ۳۸.۱۰ تنظیمات سرور

| متغیر `.env`                  | کاربرد                                        |
|-------------------------------|-----------------------------------------------|
| `SMS_PANEL_URL`               | آدرس پیش‌فرض سامانهٔ پیامک                     |
| `SMS_PANEL_ENDPOINT`          | مسیر ارسال پیامک                              |
| `SMS_PANEL_LINE`              | شماره خط ارسال                                |
| `SMS_WALLET_ENDPOINT`         | مسیر کیف پول؛ بدون آن به‌روزرسانی دستی `502` می‌دهد |
| `PANEL_REGISTRATION_ENDPOINT` | مسیر ساخت سامانه؛ بدون آن ثبت‌نام `502` می‌دهد  |
| `USER_REGISTRATION_API_KEY`   | کلید خود برنامه برای ثبت‌نام، نه کلید کاربران   |
| `PANEL_REGISTRATION_TYPE`     | مقدار `type` در ثبت‌نام شرکت (پیش‌فرض `legal`)  |
