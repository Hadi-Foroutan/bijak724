# نمایندگی‌های بیمه (ادمین)

[← فهرست بخش‌ها](README.md)

**پنل:** پنل ادمین — **تعداد روت:** ۱۰

نماینده‌های هر شرکت بیمه یک **درخت سه‌سطحی** هستند و همه در یک جدول (`insurance_agencies`) با ستون `level` و `parent_id` نگه داشته می‌شوند:

```
شرکت پارسیان                                  ← نماینده کشوری (level: country، parent_id: null، همیشه حقوقی) — هر شرکت بیمه فقط یکی
├── سرپرستی استان تهران                       ← نماینده استانی (level: province، state_code: 11) — برای هر استان یکی؛ حقیقی یا حقوقی
│   ├── نمایندگی 101 (حقوقی: کارگزاری سپهر)    ← نمایندگی (level: agency) — ادمین تعریف می‌کند؛ حقیقی یا حقوقی
│   └── نمایندگی 102 (حقیقی: علی احمدی)
├── سرپرستی استان فارس
└── ...
```

- **نماینده‌های کشوری و استانی** را دستور `php artisan generate-insurance-agencies` می‌سازد (بخش ۳۴.۲) و **نام می‌دهد**: کشوری «شرکت {نام شرکت بیمه}» و استانی «سرپرستی استان {نام استان}» (در `company_name`). بقیهٔ اطلاعاتشان خالی (`null`) است و ادمین بعداً با ویرایش پرشان می‌کند. ادمین آن‌ها را **نمی‌سازد و حذف نمی‌کند**.
- **نمایندگی‌ها** را ادمین زیر یک نماینده استانی (سرپرستی) می‌سازد، ویرایش، غیرفعال و حذف نرم می‌کند.
- **حقیقی / حقوقی** (`type`): نماینده کشوری همیشه `legal` است؛ استانی و نمایندگی می‌توانند `natural` (حقیقی) یا `legal` (حقوقی) باشند.
  حقوقی ← **نام شرکت** (`company_name`) و **کد شناسهٔ شرکت** (`company_national_id`)؛ حقیقی ← **نام، نام خانوادگی و کد ملی** (`first_name`، `last_name`، `national_code`).
- **کد نمایندگی** (`code`) فقط **برای هر شرکت بیمه یکتاست**: یک شرکت بیمه دو نمایندگی با کد یکسان ندارد، ولی شرکت‌های بیمهٔ دیگر می‌توانند همان کد را بزنند. پس نماینده همیشه با **`org_code` شرکت بیمه + کد نمایندگی** پیدا می‌شود؛ شرکت‌ها هم در استعلام و ثبت قرارداد این دو را می‌فرستند ([بخش ۱۵](15-insurances.md)).
- به **هر سه سطح** می‌شود کاربر نقش `insurance` داد ([بخش ۲۱](21-admin-users.md)) و آن کاربر وارد پنل بیمه ([بخش ۳۵](35-insurance-panel.md)) می‌شود؛ سطح نماینده تعیین می‌کند چه بارنامه‌هایی را ببیند.
- ادمین شرکت‌هایی را که با هر نماینده قرارداد بیمه دارند می‌بیند و می‌تواند شرکتی را به آن وصل یا از آن قطع کند.

(گروه‌های «مدیریت نمایندگی‌های بیمه» و «مشاهده شرکت‌های بیمه (ادمین)»). روت جدیدی برای درخت اضافه نشده؛ همان روت ۳۴.۱ با `tree=1` است.

### ۳۴.۲ ساخت نماینده‌های کشوری و استانی (دستور)

```bash
php artisan generate-insurance-agencies
```

- برای **هر شرکت بیمه** (فعال و غیرفعال) اگر نماینده کشوری نداشته باشد یکی می‌سازد (`parent_id: null`، `type: legal`، `company_name: "شرکت {نام شرکت بیمه}"`، و اگر نام شرکت بیمه خودش با «شرکت» شروع می‌شود همان نام بدون تکرار، مثلاً «شرکت بیمه ایران»)؛ هر شرکت بیمه **فقط یک** نماینده کشوری دارد.
- زیر هر نماینده کشوری، برای **هر استان** (`states`) که نماینده استانی ندارد یکی می‌سازد (`parent_id` = نماینده کشوری، `state_code` = کد استان، `type: legal`، `company_name: "سرپرستی استان {نام استان}"`).
- نماینده‌های جدید جز نام، خالی‌اند: `code`، `company_national_id`، نام، کد ملی، شهر، تماس و آدرس `null`، `status: active`. ادمین بعداً با ویرایش پرشان می‌کند.
- اجرای دوباره بی‌خطر است و فقط کمبودها را می‌سازد؛ نماینده‌ای که ادمین ویرایش کرده دست نمی‌خورد. بعد از اضافه‌شدن شرکت بیمه یا استان جدید دوباره اجرایش کنید. خروجی: `Country agents created: N, province agents created: M.`
- نماینده‌هایی که قبلاً (بدون نام) ساخته شده بودند را مایگریشن این تغییر نام‌گذاری می‌کند (کشوری‌ها `legal` + «شرکت …» و استانی‌هایی که هنوز نام و نام خانوادگی ندارند `legal` + «سرپرستی استان …»).
- نمایندگی‌ها (سطح سوم) خودکار ساخته نمی‌شوند.

### ۳۴.۳ دادهٔ کمکی برای فرم‌ها

توجه: لیست‌های `/api/user/general/...` مخصوص پنل شرکت‌اند و برای ادمین `403` می‌دهند؛ از این‌ها استفاده کنید:

| dropdown                         | روت                                                                                | مقداری که باید ارسال شود                    |
|----------------------------------|------------------------------------------------------------------------------------|---------------------------------------------|
| نماینده استانی (فرم نمایندگی)   | `GET /api/admin/insurance-agencies?tree=1` (درخت؛ فقط گره‌های `level: province` قابل انتخاب) یا `GET /api/admin/insurance-agencies?eq-level=province&eq-insurance_company_id=<شرکت بیمه>` | `id2` گره درخت / `id` ردیف → فیلد `parent_id` |
| شهر                              | `GET /api/admin/cities` (بدون `paginate` = آرایهٔ کامل) با فیلتر `eq-state_id=<استان>` ([بخش ۲۳](23-admin-cities.md)) | `code` شهر (نه `id`) → فیلد `city_code`؛ فقط شهرهای استانِ نماینده استانی پذیرفته می‌شود |
| نماینده (فرم کاربر بیمه)         | `GET /api/admin/insurance-agencies?tree=1` (هر سه سطح قابل انتخاب)                 | `id2` گره → فیلد `insurance_agency_id`      |
| شرکت بیمه (فیلتر لیست)           | `GET /api/admin/insurance-companies` (روت ۳۴.۹)                                     | `id` → فیلتر `eq-insurance_company_id`      |

برای فیلتر شهر بر اساس استانِ نماینده استانی، `state.id` همان گره/ردیف را در `GET /api/admin/cities?eq-state_id=<state.id>` بگذارید.

خروجی `GET /api/admin/insurance-companies`: آرایه (یا paginator با `paginate=1`) از شرکت‌های بیمهٔ **فعال**؛ هر ردیف دست‌کم `id`، `org_code`، `name` و `logo_url` (نشانی لوگو یا `null`) دارد. جست‌وجو با `search` یا `name=`.

### ۳۴.۴ ورودی

#### ایجاد نمایندگی (`POST`) — همیشه سطح `agency`

نمایندگی **حقوقی**:

```json
{
  "parent_id": 14,
  "type": "legal",
  "code": "101",
  "company_name": "کارگزاری سپهر",
  "company_national_id": "14001234567",
  "city_code": 1101,
  "mobile": "09121111111",
  "phone": "02122222222",
  "fax": "02133333333",
  "email": "info@sepehr.example",
  "address": "تهران، ...",
  "description": "توضیحات",
  "status": "active"
}
```

نمایندگی **حقیقی** به‌جای `company_name` و `company_national_id` این‌ها را دارد: `"type": "natural"`، `"first_name": "علی"`، `"last_name": "احمدی"`، `"national_code": "0012345678"`.

| فیلد                        | قاعده                                        | توضیح                                                                                   |
|-----------------------------|----------------------------------------------|-----------------------------------------------------------------------------------------|
| `parent_id`!                | `id` یک نماینده **استانی** حذف‌نشده          | سرپرستیِ نمایندگی؛ شرکت بیمه (`insurance_company_id`) و استان (`state_code`) از همین نماینده گرفته می‌شود. نماینده کشوری یا نمایندگی دیگر → `422` «نمایندگی فقط زیر یک نماینده استانی تعریف می‌شود.» |
| `type`!                     | `natural` (حقیقی) یا `legal` (حقوقی)         | تعیین می‌کند کدام گروه از فیلدهای هویتی الزامی است                                      |
| `company_name`!             | فقط `legal`؛ رشته، حداکثر ۲۵۵                | نام شرکت                                                                                |
| `company_national_id`!      | فقط `legal`؛ رشته، حداکثر ۲۰                 | کد شناسهٔ (شناسهٔ ملی) شرکت                                                             |
| `first_name`!، `last_name`! | فقط `natural`؛ رشته، حداکثر ۲۵۵              | نام و نام خانوادگی                                                                      |
| `national_code`!            | فقط `natural`؛ رشته، حداکثر ۲۰               | کد ملی                                                                                  |
| `code`!                     | رشته، حداکثر ۲۵۵، **یکتا در همان شرکت بیمه** | کد نمایندگی. شرکت بیمهٔ دیگر می‌تواند همین کد را داشته باشد. حتی بعد از حذف نرم، برای همان شرکت بیمه تکراری نمی‌شود |
| `city_code`!                | **کد** شهر موجود (`cities.code`، نه `id`) **در استانِ** نماینده استانی | سرور از روی کد شهر را پیدا و با `city_id` به نماینده لینک می‌کند؛  شهر دیگر → `422` «شهر نمایندگی باید در استانِ نماینده استانی آن باشد.»                 |
| `mobile`، `phone`، `fax`    | رشتهٔ اختیاری (`null` مجاز)، حداکثر ۳۰       | شمارهٔ تماس                                                                             |
| `email`                     | ایمیل اختیاری (`null` مجاز)، حداکثر ۲۵۵      |                                                                                         |
| `address`، `description`    | متن اختیاری (`null` مجاز)                    | آدرس و توضیحات                                                                          |
| `status`                    | `active` (پیش‌فرض) یا `inactive`             | نماینده غیرفعال برای استعلام و ثبت قرارداد جدید پیدا نمی‌شود                            |

فیلدهای هویتیِ **گروه دیگر** (مثلاً `first_name` برای `legal`) اگر فرستاده شوند نادیده گرفته و ذخیره‌شده‌شان `null` می‌شود. `level`، `insurance_company_id` و `state_code` ورودی نیستند و نادیده گرفته می‌شوند.

#### ویرایش (`PUT|PATCH`) — هر سطح

فقط کلیدهایی که بفرستید عوض می‌شوند. `level`، شرکت بیمه و `state_code` هیچ‌وقت مستقیم ویرایش نمی‌شوند (نادیده گرفته می‌شوند).

| فیلد                                      | نماینده **کشوری / استانی**                                   | **نمایندگی**                                                         |
|-------------------------------------------|---------------------------------------------------------------|----------------------------------------------------------------------|
| `type`                                    | کشوری: فقط `legal`؛ استانی: `natural` یا `legal`              | `natural` یا `legal`؛ با تغییر نوع، فیلدهای هویتیِ نوع جدید **الزامی** می‌شوند و فیلدهای نوع قبلی `null` می‌شوند |
| `company_name`، `company_national_id`     | اختیاری، `null` مجاز                                          | اگر نوع `legal` است و فرستاده شود خالی نباشد                          |
| `first_name`، `last_name`، `national_code` | اختیاری، `null` مجاز (کشوری: نادیده گرفته می‌شود)            | اگر نوع `natural` است و فرستاده شود خالی نباشد                        |
| `code`                                    | اختیاری، `null` مجاز، یکتا در همان شرکت بیمه                  | اگر فرستاده شود خالی نباشد، یکتا در همان شرکت بیمه                    |
| `city_code`                               | اختیاری، `null` مجاز؛ کشوری: هر شهری، استانی: شهری از استان خودش | اگر فرستاده شود خالی نباشد؛ شهری از استانِ نماینده استانی‌اش        |
| `parent_id`                               | پذیرفته نمی‌شود (نادیده)                                      | انتقال به نماینده استانی دیگر؛ در این حالت `city_code` **الزامی** است و باید در استان جدید باشد. شرکت بیمه و `state_code` از نماینده جدید گرفته می‌شود و `code` باید در شرکت بیمهٔ جدید تکراری نباشد |
| `mobile`، `phone`، `fax`، `email`، `address`، `description` | اختیاری، `null` مجاز                      | اختیاری، `null` مجاز                                                 |
| `status`                                  | `active` / `inactive`                                         | `active` / `inactive`                                                |

برای فرم ویرایش، فرم را با مقادیر `GET .../{id}` پر کنید و گروه فیلدهای هویتی را با `type` عوض کنید؛ برای نماینده کشوری/استانی فیلدها اجباری نیستند و فیلد `parent_id` را نشان ندهید (کشوری: انتخاب نوع را هم نشان ندهید، همیشه حقوقی است).

### ۳۴.۵ خروجی یک نماینده

پاسخ ایجاد `201` است؛ پاسخ ویرایش و جزئیات `200`:

```json
{
  "success": true,
  "message": "نمایندگی بیمه با موفقیت ایجاد شد",
  "data": {
    "id": 52,
    "parent_id": 14,
    "title": "101 - کارگزاری سپهر",
    "code": "101",
    "insurance_company_id": 3,
    "insurance_company": { "id": 3, "org_code": 201, "name": "پارسیان" },
    "state_code": 11,
    "state": { "id": 1, "code": 11, "name": "تهران" },
    "city_id": 5,
    "city_code": 1101,
    "city": { "id": 5, "code": 1101, "name": "تهران" },
    "level": "agency",
    "level_label": "نمایندگی",
    "type": "legal",
    "type_label": "حقوقی",
    "company_name": "کارگزاری سپهر",
    "company_national_id": "14001234567",
    "first_name": null,
    "last_name": null,
    "national_code": null,
    "full_name": "",
    "name": "کارگزاری سپهر",
    "mobile": "09121111111",
    "phone": "02122222222",
    "fax": "02133333333",
    "email": "info@sepehr.example",
    "address": "تهران، ...",
    "description": "توضیحات",
    "status": "active",
    "created_at": "2026-11-04T09:30:00.000000Z",
    "updated_at": "2026-11-04T09:30:00.000000Z"
  }
}
```

- `name`: نام نماینده؛ حقوقی ← `company_name`، حقیقی ← `full_name` (نام و نام خانوادگی). برای حقوقی `full_name` رشتهٔ خالی و `first_name`/`last_name`/`national_code` برابر `null` است؛ برای حقیقی `company_name` و `company_national_id` برابر `null`.
- `title`: نام نمایشی برای لیست و درخت، حتی وقتی نماینده هنوز نامی ندارد:
  کشوری ← `name` (پیش‌فرض «شرکت {شرکت بیمه}»)؛ استانی ← `name` برای حقوقی (پیش‌فرض «سرپرستی استان {استان}») و «سرپرستی استان {استان} - {نام}» برای حقیقی؛ نمایندگی ← «{code} - {name}».
- نماینده کشوری: `parent_id`، `state_code` و `state` برابر `null`. نماینده تازه‌ساخته: `code`، `company_national_id`، `city_code`، تماس و … `null`.

#### لیست ساده

`GET /api/admin/insurance-agencies` از دستور مشترک لیست ([بخش ۱](01-general-conventions.md)) پیروی می‌کند و جدیدترین‌ها اول می‌آیند. با `paginate=1` شیء paginator
و بدون آن آرایهٔ ساده برمی‌گردد. ردیف‌ها همان شکل بالا را دارند.

| پارامتر                            | اثر                                                              |
|------------------------------------|------------------------------------------------------------------|
| `search=text`                      | جست‌وجو روی کد، نام شرکت، شناسهٔ شرکت، نام، نام خانوادگی، کد ملی، موبایل، تلفن و ایمیل |
| `eq-level=country\|province\|agency` | نماینده‌های یک سطح                                             |
| `eq-type=natural\|legal`          | فقط حقیقی‌ها یا فقط حقوقی‌ها                                      |
| `eq-parent_id=14`                  | نمایندگی‌های زیر یک نماینده استانی (یا استانی‌های زیر یک کشوری)  |
| `eq-status=active\|inactive`       | فیلتر وضعیت                                                      |
| `eq-insurance_company_id=3`        | نماینده‌های یک شرکت بیمه                                          |
| `insuranceCompany__org_code=201`   | نماینده‌های شرکت بیمه با این `org_code`                           |
| `eq-state_code=11`                 | نماینده استانی و نمایندگی‌های یک استان                            |
| `state__name=تهران`                | جست‌وجو روی نام استان                                            |
| `eq-city_id=5`                     | نماینده‌های یک شهر (با `id` شهر)                                  |
| `city__code=1101`                  | نماینده‌های شهر با این **کد** شهر                                 |
| `code=AG`                          | شامل این متن در کد                                               |
| `insuranceCompany__name=پارس`      | جست‌وجو روی نام شرکت بیمه                                        |
| `order_field`، `order_type`        | مرتب‌سازی                                                        |

#### لیست درختی (`tree=1`)

دقیقاً مثل لیست درختی کاربران/شرکت‌ها ([بخش ۲۱](21-admin-users.md)): `GET /api/admin/insurance-agencies?tree=1` آرایه‌ای از ریشه‌ها برمی‌گرداند (بدون صفحه‌بندی).
ریشه‌ها نماینده‌های کشوری‌اند، `children` آن‌ها نماینده‌های استانی و `children` استانی‌ها نمایندگی‌ها. فیلترهای لیست ساده هم کار می‌کنند
(مثلاً `tree=1&eq-insurance_company_id=3` فقط درخت یک شرکت بیمه)؛ گره‌ای که والدش در نتیجه نباشد خودش ریشه می‌شود.

```json
{
  "success": true,
  "data": [
    {
      "id": "1",
      "label": "شرکت پارسیان",
      "id2": 13,
      "parent_id": null, "level": "country", "type": "legal", "title": "شرکت پارسیان", "code": null, "...": "سایر فیلدهای ۳۴.۵ (بدون id)",
      "children": [
        {
          "id": "1-1",
          "label": "سرپرستی استان تهران",
          "id2": 14,
          "parent_id": 13, "level": "province", "state": { "id": 1, "code": 11, "name": "تهران" }, "...": "...",
          "children": [
            { "id": "1-1-1", "label": "101 - کارگزاری سپهر", "id2": 52, "parent_id": 14, "level": "agency", "...": "...", "children": [] }
          ]
        }
      ]
    }
  ]
}
```

- `id` رشتهٔ مسیر در درخت است (`"1-1-1"`) برای کامپوننت tree؛ **شناسهٔ واقعی نماینده `id2` است** (برای `insurance_agency_id` و `parent_id` همین را بفرستید).
- `label` همان `title` است.

### ۳۴.۶ حذف و غیرفعال‌سازی

- **حذف** (`DELETE`) فقط برای سطح **نمایندگی** و نرم است: پاسخ `data: []` با پیام موفقیت. نمایندگی از لیست و استعلام کنار می‌رود و `GET .../{id}` برایش `404` می‌دهد، ولی ردیف و قراردادهایش در دیتابیس می‌مانند و **کدش دوباره قابل استفاده نیست**.
  endpoint «بازیابی» یا «لیست حذف‌شده‌ها» وجود ندارد؛ در UI قبل از حذف تأیید بگیرید.
- حذف نماینده **کشوری یا استانی** `422` با پیام «نماینده کشوری و استانی حذف نمی‌شود؛ فقط نمایندگی‌ها قابل حذف هستند.» می‌دهد؛ در UI دکمهٔ حذف را برای این دو سطح نشان ندهید. برای از کار انداختنشان غیرفعالشان کنید.
- **غیرفعال‌کردن**: `PATCH` با `{ "status": "inactive" }`. نماینده غیرفعال در استعلام شرکت‌ها پیدا نمی‌شود و قرارداد جدید با آن ثبت نمی‌شود؛ قراردادهای قبلی و پنل بیمهٔ آن سر جایش است. فعال‌کردن دوباره: `{ "status": "active" }`.

### ۳۴.۷ اتصال قرارداد بیمهٔ یک شرکت به نماینده

نماینده به **قرارداد بیمهٔ یک شرکت** وصل می‌شود، نه به خودِ شرکت. روند فرم ادمین:

1. شرکت را از `GET .../companies/unconnected` انتخاب کند (همهٔ شرکت‌هایی که هنوز هیچ قراردادی به این نماینده ندارند؛ `?search=` روی نام یا کد سازمانی)؛ شرکت‌های دارای قرارداد متصل از `GET .../companies` می‌آیند؛
2. با `GET /api/admin/insurance-agencies/{id}/companies/{company}/insurances` قراردادهای آن شرکت با **همان شرکت بیمهٔ نماینده** را بگیرد؛
3. یکی از قراردادها را انتخاب و با `POST .../insurances` وصل کند.

**`GET .../companies`** — شرکت‌های دارای قرارداد متصل (فعال یا قطع‌شده): `[{ "company_id", "name", "organization_code", "insurances_count", "active_insurances_count" }]`.
**`GET .../companies/unconnected`** — شرکت‌های متصل‌نشده: `[{ "company_id", "name", "organization_code" }]`. هر دو لیست آرایهٔ ساده‌اند. برای وصل‌کردن قرارداد دیگری از شرکتِ از قبل متصل، مستقیم به `GET .../companies/{company}/insurances` بروید.

**`GET .../companies/{company}/insurances`** — قراردادهای شرکت با شرکت بیمهٔ این نماینده (آرایهٔ ساده، بدون صفحه‌بندی). اگر شرکت قراردادی با شرکت بیمهٔ این نماینده ندارد، آرایه خالی است و باید پیام «این شرکت قرارداد بیمه‌ای با این شرکت بیمه ندارد» نشان داده شود.

**`GET .../insurances`** — قراردادهایی که به این نماینده وصل‌اند (فعال یا قطع‌شده). هر دو لیست یک ساختار دارند:

```json
{ "success": true, "message": "...", "data": [ {
  "insurance_id": 31, "title": "بیمه باربری", "contract_number": "C-1", "status": "active",
  "start_date": "2026-01-01", "end_date": "2026-12-31",
  "company_id": 12, "company_name": "شرکت نمونه", "organization_code": "2488955",
  "connection": "active", "connected_insurance_agency_id": 5
} ] }
```

- `connection`: `active` = وصل به **این** نماینده، `inactive` = اتصال را ادمین قطع کرده، `null` = به این نماینده وصل نیست.
- `connected_insurance_agency_id`: نمایندهٔ فعلی قرارداد (`null` = بدون نماینده). اگر مقدارش غیر از این نماینده بود، قرارداد را برای انتخاب غیرفعال نشان دهید.

**`POST .../insurances`** با `{ "insurance_id": 31 }` قرارداد را وصل می‌کند (یا اتصال قطع‌شده را دوباره فعال می‌کند) و **لیست قراردادهای متصل** (`GET .../insurances`) را برمی‌گرداند. خطاها:
- `422` روی `insurance_id`: قرارداد وجود ندارد؛
- `422` (`errors.error[0]`): شرکت بیمهٔ قرارداد با شرکت بیمهٔ نماینده یکی نیست؛ قرارداد به نمایندهٔ دیگری وصل است؛ یا نماینده سطح «نمایندگی» نیست (کشوری/استانی قرارداد نمی‌گیرند).

**`DELETE .../insurances/{insurance}`** اتصال را قطع می‌کند (`connection` می‌شود `inactive`) و لیست به‌روز را برمی‌گرداند. قراردادی که به این نماینده تعلق ندارد `404` می‌دهد. برای وصل‌کردن دوبارهٔ **همان قرارداد** همان `POST` را بزنید.

آثار **قطع اتصال** (فقط روی همان قرارداد؛ قراردادهای دیگر شرکت دست‌نخورده می‌مانند):
- بارنامه‌هایی که با آن قرارداد بیمه شده‌اند در پنل بیمهٔ این نماینده (و بالادستی‌هایش: استانی و کشوری) دیده نمی‌شوند؛
- شرکت در جزئیات قرارداد (`GET /api/user/insurances/{id}`) `insurance_agency_status: "inactive"` و `insurance_agency: null` می‌بیند و نمی‌تواند نمایندهٔ آن قرارداد را عوض کند (`422` با پیام «ارتباط این قرارداد با نمایندگی بیمه توسط ادمین قطع شده است.»)؛
- قرارداد پاک نمی‌شود و با اتصال دوباره همه چیز برمی‌گردد.

آثار **اتصال**: شرکت در جزئیات همان قرارداد (`GET /api/user/insurances/{id}`) اطلاعات نماینده را می‌بیند (`insurance_agency_status: "active"`، `insurance_agency{id, code, city_code}` و فیلدهای `representative_*` از روی نماینده).
قراردادی که شرکت خودش با `insurance_agency_code` ثبت می‌کند همان لحظه به همان نماینده وصل (`active`) می‌شود.

### ۳۴.۸ ورود ادمین به پنل نماینده (`login-as`)

**`POST /api/admin/insurance-agencies/{id}/login-as`** بدون بدنه. ادمین (نقش `admin` یا `superAdmin`) با آن به پنل بیمهٔ همان نماینده (هر سطح) وارد می‌شود، مثل «ورود به شرکت» در [بخش ۳](03-auth.md).
پاسخ `201` است و همان ساختار ورود را دارد، با `auth_mode: "insurance_support"` و کلید `insurance_access`:

```json
{
  "success": true,
  "message": "توکن موقت پشتیبانی صادر شد",
  "data": {
    "token": "21|plain-text-token",
    "user": { "id": 1, "full_name": "ادمین" },
    "role": { "id": 6, "name": "insurance", "display_name": "نمایندگی بیمه" },
    "permissions": ["insurance.companies.index", "insurance.companies.waybills.index", "insurance.companies.waybills.show"],
    "auth_mode": "insurance_support",
    "insurance_access": {
      "access_type": "support", "level": "agency", "level_label": "نمایندگی",
      "insurance_company": { "id": 3, "name": "پارسیان" },
      "agency": { "id": 52, "parent_id": 14, "title": "101 - کارگزاری سپهر", "code": "101", "...": "شکل ۳۴.۵" },
      "city": { "code": 1101, "name": "تهران" }, "state": { "id": 1, "code": 11, "name": "تهران" },
      "issued_by": { "id": 1, "full_name": "ادمین" },
      "permissions": ["..."],
      "expires_at": "2026-11-05T09:30:00+03:30"
    }
  }
}
```

- توکن ۱ روز اعتبار دارد (`expires_at`) و فقط به `/api/insurance/*` دسترسی دارد؛ در آن محدودهٔ همین نماینده با **سطح خودش** اعمال می‌شود ([بخش ۳۵](35-insurance-panel.md)).
- دیدِ ادمین دقیقاً همان دیدِ کاربران آن نماینده است: نماینده کشوری = همهٔ قراردادهای شرکت بیمه، استانی = خودش و نمایندگی‌های زیرش، نمایندگی = فقط خودش.
- `state`: برای استانی و نمایندگی از `state_code` نماینده، برای کشوری از شهر دفترش (اگر پر شده باشد) وگرنه `null`. `city`: از `city_code` نماینده، وقتی خالی است `null`.
- نماینده غیرفعال هم قابل ورود است (ادمین بررسی می‌کند)؛ نماینده حذف‌شده `404` می‌دهد. اگر نقش `insurance` در سیستم نباشد `422` («نقش نمایندگی بیمه یافت نشد»).
- کاربر غیر ادمین `403` می‌گیرد. توکن ادمین را نگه دارید؛ برای بازگشت به پنل ادمین توکن پشتیبانی را دور بریزید (یا `POST /api/auth/logout`).
- UI: در درخت/صفحهٔ نماینده دکمهٔ «ورود به پنل» (با مجوز `admin.insurance-agencies.loginAs`) بگذارید و بعد از پاسخ، مثل ورود عادی به پنل بیمه بروید.

### ۳۴.۹ خطاها

| وضعیت | چه زمانی                                                                        | بدنه                                                                                          |
|-------|---------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------|
| `422` | فیلد الزامی/نامعتبر (از جمله فیلدهای هویتیِ `type`)، کد تکراری در همان شرکت بیمه، والد غیر استانی، شهر خارج از استان | `{ success:false, message, errors: { code: ["..."], parent_id: ["..."], city_code: ["..."] } }` |
| `422` | حذف نماینده کشوری/استانی                                                         | `{ success:false, message, errors: { error: ["نماینده کشوری و استانی حذف نمی‌شود؛ ..."] } }`   |
| `404` | نماینده یا اتصال یافت نشد / حذف‌شده                                              | `{ success:false, message, errors: { error: ["..."] } }`                                       |
| `403` | کاربر مجوز روت را ندارد                                                          | `{ message }`                                                                                  |

### ۳۴.۱۰ پیشنهاد صفحه‌ها در UI

1. **درخت نماینده‌ها** (`tree=1`): شرکت بیمه ← کشوری ← استان‌ها ← نمایندگی‌ها، با فیلتر شرکت بیمه (`eq-insurance_company_id`) و جست‌وجو. روی هر گره: ویرایش، فعال/غیرفعال، «شرکت‌ها»، «ورود به پنل»؛ روی گرهٔ استانی: «افزودن نمایندگی» (فرم با `parent_id` همان گره)؛ روی گرهٔ نمایندگی: حذف (با تأیید).
2. **فرم نمایندگی** (ایجاد/ویرایش سطح agency): انتخاب «حقیقی / حقوقی» (`type`)؛ حقوقی ← نام شرکت و کد شناسهٔ شرکت، حقیقی ← نام، نام خانوادگی و کد ملی؛ سپس کد نمایندگی، شهر (فقط شهرهای استانِ سرپرستی)، تماس، ایمیل، آدرس و توضیحات؛ خطاهای `422` را زیر فیلد همنام نشان دهید. خطای تکراری‌بودن `code` یعنی همین شرکت بیمه این کد را قبلاً دارد.
3. **فرم ویرایش کشوری/استانی**: همان فیلدها ولی همه اختیاری، بدون `parent_id`؛ کشوری همیشه حقوقی است (انتخاب نوع نشان داده نشود)، استانی می‌تواند نوع را عوض کند؛ شهر استانی محدود به استان خودش.
4. **صفحهٔ قراردادهای نماینده**: جدول ۳۴.۶ (شرکت، قرارداد، وضعیت اتصال، دکمهٔ «قطع/وصل») و فرم «افزودن»: انتخاب شرکت ← انتخاب یکی از قراردادهایش (۳۴.۷).
