# ۳۰. گزارش‌های پرکاربرد

انواع آمادهٔ گزارش (بیمه، بیمه بارگیر، بارگیر، خلاصه حسابداری، ...) که برای یک بازهٔ تاریخی به‌صورت PDF یا Excel خروجی می‌گیرند.
این بخش **جدا از گزارش‌ساز** است (`/api/user/frequent-reports` در برابر `/api/user/reports`؛ مجوزها: `user.frequent-reports.*`).

**عنوان، ستون‌ها، شرط‌های ثابت و فیلترهای هر نوع را بک‌اند تعیین می‌کند؛ فرانت فقط «نوع» و مقدار فیلترهای همان نوع را می‌فرستد.**
فیلتر یا مقداری که جزو فیلترهای آن نوع نباشد نادیده گرفته می‌شود (مثلاً فرانت نمی‌تواند وضعیت یا شرط بیمه‌دار بودن را عوض کند).

مسیر ساخت خروجی همان گزارش‌ساز است ([28-report-builder.md](28-report-builder.md)): در صف ساخته می‌شود، وضعیتش با سوکت اعلام می‌شود، در
«گزارش‌های اخیر» (`/report-exports`) دیده می‌شود، لینک دانلود موقت دارد و بعد از مدت نگهداری حذف می‌شود.

## نحوهٔ کار (از درخواست تا دانلود)

| مرحله | چه اتفاقی می‌افتد |
|-------|-------------------|
| ۱ | فرانت `GET /frequent-reports` را می‌زند و برای هر نوع، عنوان و فیلترها (`filters`) را می‌گیرد و فرم می‌سازد. |
| ۲ | کاربر نوع، فرمت (`xlsx`/`pdf`) و بازه را انتخاب می‌کند؛ فرانت `POST /frequent-reports/{type}/exports` می‌زند. |
| ۳ | بک‌اند فوراً پاسخ `202` می‌دهد (گزارش ساخته نشده، فقط **در صف** قرار گرفته) و رویداد سوکت `report-export.queued` را می‌فرستد. |
| ۴ | worker صف گزارش را برمی‌دارد: وضعیت `processing` + رویداد `report-export.processing`. |
| ۵ | فایل ساخته می‌شود: وضعیت `completed` + رویداد `report-export.completed` که `download_url` دارد. اگر خطا شد `failed` + `error`. |
| ۶ | کاربر لینک را باز می‌کند (بدون توکن) و فایل دانلود می‌شود. بعد از مدت نگهداری (پیش‌فرض ۸ ساعت، تنظیم ادمین) فایل و رکورد حذف می‌شوند. |

فرانت لازم نیست منتظر بماند: اگر سوکت وصل است رویدادها می‌رسند؛ اگر نه، با `GET /report-exports` (یا `/report-exports/{id}`) وضعیت را بخواند.

### فرانت چه می‌فرستد؟

فقط **نوع** (در آدرس)، **فرمت** و **بازهٔ تاریخ**. عنوان، ستون‌ها، شرط‌های ثابت و فیلترهای دیگر را بک‌اند تعیین می‌کند.

```http
POST /api/user/frequent-reports/insurance/exports
Authorization: Bearer <token>

{ "format": "pdf", "filters": { "issued_from": "2026-10-25", "issued_to": "2026-10-26" } }
```

### پاسخ فوری (`202`)

```json
{
  "success": true,
  "message": "درخواست گزارش ثبت شد و در صف آماده‌سازی قرار گرفت",
  "data": {
    "id": 41,
    "template": "insurance",
    "name": "گزارش بیمه",
    "format": "pdf",
    "status": "queued",
    "status_label": "در صف",
    "filters": { "issued_from": "2026-10-25", "issued_to": "2026-10-26" },
    "rows_count": null, "file_size": null, "error": null,
    "started_at": null, "completed_at": null, "expires_at": null,
    "created_at": "2026-10-29T10:15:01+03:30",
    "download_url": null
  }
}
```

هنوز فایلی نیست: `download_url` `null` است. `id` را نگه دارید تا رویدادها و لیست را با آن تطبیق دهید.

### رویدادهای سوکت

کانال خصوصی `private-users.{userId}.reports` (فقط خود کاربر؛ جزئیات اتصال در [29-socket.md](29-socket.md)). با Echo نام رویداد با نقطهٔ ابتدایی است:

| رویداد | وقتی |
|--------|------|
| `.report-export.queued` | درخواست ثبت و در صف قرار گرفت |
| `.report-export.processing` | worker شروع به ساخت کرد |
| `.report-export.completed` | فایل آماده است؛ `export.download_url` را دارد |
| `.report-export.failed` | ساخت ناموفق بود؛ `export.error` علت را دارد |
| `.report-export.expired` | مدت نگهداری تمام شد و گزارش حذف شد (آن را از لیست بردارید) |

بدنهٔ `completed`:

```json
{ "company_id": 3,
  "export": { "id": 41, "template": "insurance", "name": "گزارش بیمه", "format": "pdf", "status": "completed",
              "status_label": "تکمیل شده", "rows_count": 26, "file_size": 51469,
              "expires_at": "2026-10-29T18:15:09+03:30",
              "download_url": "https://api.example.com/report-exports/41/download?expires=...&signature=..." } }
```

### دانلود

`download_url` لینک موقت امضاشده است؛ مستقیم باز شود (بدون هدر `Authorization`). فقط برای وضعیت `completed` و تا `expires_at` معتبر است
(بعد از آن `403` یا فایل حذف‌شده). پسوند و نوع فایل از `format` است: `.xlsx` یا `.pdf`.

### خطاها

| وضعیت | علت |
|--------|------|
| `404` | نوع ناشناخته |
| `422` | فیلتر اجباری نیامده/نامعتبر (`filters.issued_from`، `filters.issued_to` بعد از شروع)، یا فرمت نامعتبر، یا ۵ درخواست فعال دارد (در صف یا در حال ساخت) |
| `403` | کاربر مجوز `user.frequent-reports.*` ندارد |
| رویداد `failed` | تعداد بارنامه‌ها از سقف گذشت (۳۰٬۰۰۰ برای Excel، ۵٬۰۰۰ برای PDF) یا خطای ساخت؛ پیام در `error` است |

### گزارش‌ساز تغییری نکرده است

گزارش‌ساز (`/api/user/reports`، `/report-exports`) همان قرارداد قبلی را دارد: کاربر خودش فیلدها، فیلترها، ترتیب، تراز و عرض ستون‌ها را
انتخاب می‌کند. گزارش‌های پرکاربرد فقط یک مسیر جدا کنارش هستند و ساخت فایل، صف، سوکت، لیست «گزارش‌های اخیر»، دانلود و حذف خودکار را با آن
**مشترک** دارند؛ یعنی یک خروجی پرکاربرد هم در `GET /report-exports` می‌آید (با `template` پر و `report_definition_id` خالی).

## نوع‌ها را از کجا پیدا کنم؟ (قاعدهٔ ارسال)

**مرجع، پاسخ `GET /api/user/frequent-reports` است** (فیلد `type` هر آیتم)؛ فرانت نوع‌ها را در کد ثابت نکند و از همین لیست بسازد.
مقدارِ `type` همان **کلید نوع در `config/report_templates.php`** است و در آدرس می‌رود: `POST /frequent-reports/{type}/exports`.

قاعده: کلید فقط حروف کوچک انگلیسی و عدد، با خط تیره (`kebab-case`)؛ بعد از انتشار عوض نمی‌شود (عنوان فارسی را می‌شود عوض کرد، کلید را نه).

| `type` | عنوان | چیدمان |
|--------|-------|--------|
| `insurance` | گزارش بیمه | جدول |
| `loader-insurance` | گزارش بیمه بارگیر | جدول |
| `loader-insurance-cargo-value` | گزارش بیمه بارگیر و ارزش محموله | جدول |
| `loader` | گزارش بارگیر | جدول گروه‌بندی‌شده (به نوع کامیون) |
| `accounting-summary` | خلاصه گزارش حسابداری | خلاصه |

## لیست انواع

`GET /api/user/frequent-reports` — مجوز: `user.frequent-reports.index`

```json
{ "data": [ { "type": "insurance", "title": "گزارش بیمه", "layout": "table", "orientation": "auto",
              "filters": [ { "key": "issued_from", "label": "از تاریخ", "type": "date", "required": true },
                           { "key": "issued_to", "label": "تا تاریخ", "type": "date", "required": true } ],
              "columns": [ { "key": "row", "label": "ردیف", "type": "index", "sum": false }, ... ] } ] }
```

فرانت از `filters` فرم می‌سازد. `layout`: `table` (جدول) یا `summary` (خلاصه). `type` ستون: `index` · `text` · `date` (تاریخ شمسی) ·
`number` (جداکنندهٔ سه‌رقمی). `sum: true` یعنی آخر گزارش جمع این ستون هم نوشته می‌شود.

## درخواست خروجی

`POST /api/user/frequent-reports/{type}/exports` — مجوز: `user.frequent-reports.exports.store` — پاسخ `202` (مثل `/reports/{report}/exports`)

| فیلد | قاعده |
|------|-------|
| `format`! | `xlsx` یا `pdf` |
| `filters.<key>` | مقدار هر فیلتری که آن نوع دارد (`filters` همان لیست بالا)؛ فیلتر «اجباری» باید باشد |

برای همهٔ نوع‌های فعلی: `filters.issued_from`! (تاریخ شروع، میلادی `2026-10-25`) و `filters.issued_to`! (تاریخ پایان، بعد از یا برابر شروع؛ کل **روز
پایان** تا ۲۳:۵۹ حساب می‌شود). نوع ناشناخته → `404`. پاسخ همان `ReportExportResource` است با `template` (کلید نوع) و `name` (عنوان نوع).
بارنامه‌هایی که کاربر اجازهٔ دیدنشان را ندارد وارد گزارش نمی‌شوند (مثل گزارش‌ساز).

## شکل فایل

- **عنوان:** `گزارش بیمه {نام شرکت} - کد سازمانی: {کد}`
- **زیرعنوان:** `گزارش از تاریخ 1405/08/03 تا 1405/08/04` (شمسی)
- **ستون‌ها:** به همان ترتیب قالب (اولین ستون سمت راست). مبلغ‌ها با جداکنندهٔ سه‌رقمی.
- **آخرین ردیف:** جمع ستون‌های عددی (پس‌زمینهٔ زرد).
- PDF: شمارهٔ صفحه `صفحه ۱ از ۱۸` در پایین هر صفحه؛ فونت و رنگ‌ها مثل بقیهٔ گزارش‌ها.

## قالب‌های موجود

### `insurance` — گزارش بیمه

فقط بارنامه‌هایی که **بیمه دارند**، به ترتیب تاریخ صدور (قدیمی‌ترین اول).

| ستون | از کجا |
|------|--------|
| ردیف | شمارهٔ ردیف |
| تاریخ | تاریخ صدور بارنامه (`issued_at`) |
| شماره بارنامه | `bijak_number` |
| سری | `serial_number` |
| مقصد | شهر آدرس گیرنده |
| محموله | نام کالاهای محموله |
| پلاک | پلاک ناوگان |
| نام / شماره بیمه | نام شرکت بیمه و شمارهٔ قرارداد بیمه (دو خط) |
| ارزش | جمع ارزش محموله‌ها (`value`) — جمع می‌خورد |
| بیمه | `insurance_amount` — جمع می‌خورد |
| مالیات ارزش افزوده | `insurance_tax_amount` — جمع می‌خورد |

### `loader-insurance` — گزارش بیمه بارگیر

همان گزارش بیمه (همان بارنامه‌ها، ترتیب، عنوان و جمع)، با یک ستون بیشتر: **نوع بارگیر** (نوع بارگیری ناوگان) بین «محموله» و «پلاک».
ستون‌ها: ردیف، تاریخ، شماره بارنامه، سری، مقصد، محموله، **نوع بارگیر**، پلاک، نام / شماره بیمه، ارزش، بیمه، مالیات ارزش افزوده.
عنوان فایل: `گزارش بیمه بارگیر {نام شرکت} - کد سازمانی: {کد}`.

### `loader-insurance-cargo-value` — گزارش بیمه بارگیر و ارزش محموله

ستون‌ها و بارنامه‌ها مثل `loader-insurance`؛ فقط کلید و عنوان فایل فرق دارد: `گزارش بیمه بارگیر و ارزش محموله {نام شرکت} - کد سازمانی: {کد}`.

### `loader` — گزارش بارگیر

یک گزارش **تجمیعی**: به‌جای یک ردیف برای هر بارنامه، **یک ردیف برای هر نوع کامیون** (نوع بارگیری ناوگان) دارد.
ستون‌ها: ردیف، نوع کامیون، تعداد، جمع وزن، میانگین وزن.

- **تعداد:** تعداد بارنامه‌های آن نوع کامیون.
- **جمع وزن:** جمع وزن مبدأ محموله‌های (`origin_weight`) همان بارنامه‌ها.
- **میانگین وزن:** جمع وزن تقسیم بر تعداد بارنامه (تا دو رقم اعشار).
- بارنامه‌ای که ناوگان یا نوع بارگیری ندارد در گروه «نامشخص» (همیشه آخر) می‌آید. گروه‌ها به ترتیب حروف هستند.
- آخرین ردیف جمع «تعداد» و «جمع وزن» است. فیلتر ثابتی ندارد (همهٔ بارنامه‌های بازه).

### `accounting-summary` — خلاصه گزارش حسابداری

یک گزارش **خلاصه** (`layout: summary`): به‌جای ردیف‌های بارنامه، هر معیار یک عدد برای کل بازه است و به‌صورت جفت‌های «شرح / مقدار»، دو معیار در هر
ردیف، چاپ می‌شود (ستون‌ها: شرح، مقدار، شرح، مقدار). مبلغ‌ها و وزن‌ها فقط از بارنامه‌هایی جمع می‌شوند که **ابطال نشده‌اند**؛ تعداد کل همهٔ بارنامه‌ها را می‌شمارد.

| معیار | محاسبه |
|-------|--------|
| تعداد کل / تعداد سالم / تعداد باطله | همهٔ بارنامه‌ها / ابطال‌نشده / ابطال‌شده |
| مجموع کمسیون شرکت | جمع `commission_amount` |
| مجموع کرایه پایه | جمع `base_freight_amount` |
| مجموع بارگیری | جمع `loading_amount` |
| مجموع باسکول | جمع `weighbridge_amount` |
| مجموع حق بیمه | جمع `insurance_amount` |
| ارزش افزوده بیمه | جمع `insurance_tax_amount` |
| مجموع بیمه و ارزش افزوده | حق بیمه + ارزش افزوده بیمه |
| دریافتی از راننده | جمع `driver_receivable_amount` |
| مجموع ارزش محموله | جمع ارزش (`value`) محموله‌ها |
| مجموع وزن مبدا | جمع وزن مبدأ (`origin_weight`) محموله‌ها |

## افزودن نوع گزارش جدید

همهٔ گزارش‌ها **یک قالب ثابت** دارند (عنوان شرکت، سطر بازه، جدول، ردیف جمع، فونت، رنگ‌ها، صف و سوکت)؛ هر نوع فقط **فهرست فیلدهایش**
را مشخص می‌کند. برای عکس/نوع جدید:

۱. در `config/report_templates.php` یک ورودی بگذارید:

```php
'insurance' => [
    'title' => 'گزارش بیمه',
    'orientation' => 'auto',              // auto | portrait | landscape (auto: landscape when more than 6 columns)
    'constraints' => ['has_insurance' => true, 'sort_by' => 'issued_at', 'sort_direction' => 'asc'],   // ثابت، فقط بک‌اند
    'filters' => ['issued_from', 'issued_to'],                                                           // آنچه فرانت می‌فرستد
    'columns' => ['row', 'date', 'bijak_number', 'serial', 'destination', 'cargo', 'plate', 'insurance', 'cargo_value', 'premium', 'vat'],
],
```

۲. `constraints` شرط‌های ثابت نوع است (فرانت نمی‌تواند عوضشان کند) و `filters` فیلترهایی است که فرانت می‌فرستد؛ نام فیلترها در
   `TemplateFilterLibrary` است (`issued_from`، `issued_to`) و در یک نوع می‌شود اجباری بودن یا عنوان را عوض کرد:
   `['filter' => 'issued_to', 'required' => false]`. فیلتر تازه را یک‌بار در `TemplateFilterLibrary` اضافه کنید.

   نام ستون‌ها در `TemplateFieldLibrary` تعریف شده است (`row`، `date`، `bijak_number`، `serial`، `destination`، `cargo`، `loading_type`،
   `plate`، `insurance`، `cargo_value`، `premium`، `vat`، و برای گزارش‌های تجمیعی `waybill_count`، `weight_sum`، `weight_avg`). ترتیب `columns` = ترتیب ستون‌ها (اولی سمت راست).

۳. برای عوض کردن عنوان یا عرض یک فیلد فقط در همان نوع: `['field' => 'cargo_value', 'label' => 'ارزش کالا', 'width' => 90]`.

۴. برای گزارش **خلاصه** (هر ستون یک عدد برای کل بازه) `'layout' => 'summary'` بگذارید و در `columns` معیارها را (`count_all`، `total_commission`، ...) بنویسید؛ نمونه: `accounting-summary`.

۵. برای گزارش تجمیعی (یک ردیف برای هر مقدار یک فیلد) `'group_by' => 'نام فیلد'` بگذارید و برای ستون‌های عددی از `waybill_count` (تعداد)،
   `weight_sum` (جمع) و `weight_avg` (میانگین) استفاده کنید؛ نمونه: `loader`.

۶. اگر نوع جدید فیلدی دارد که هنوز نیست (مثلاً «نام راننده»)، یک‌بار آن را در `TemplateFieldLibrary` اضافه کنید (کلید، عنوان، نوع،
   مسیر روی بارنامه یا closure)؛ از آن به بعد همهٔ نوع‌ها می‌توانند از آن استفاده کنند.

مسیر API، مجوز، صف، سوکت، فایل Excel/PDF، عنوان، بازهٔ تاریخ و ردیف جمع برای نوع جدید خودکار کار می‌کند. فقط اگر یک **فیلتر ثابت
جدید** لازم است که در فرم فیلتر نیست (مثل `has_insurance`)، آن را در `WaybillReportFilterApplier` اضافه کنید.

## ساختار کد (برای توسعه‌دهنده)

| چه می‌خواهم | کجا |
|--------------|-----|
| نوع جدید، ستون‌ها، شرط‌های ثابت، فیلترها | `config/report_templates.php` |
| ستون (فیلد) جدید | `TemplateFieldLibrary` |
| فیلتر جدید | `TemplateFilterLibrary` (و `WaybillReportFilterApplier` اگر شرط تازه‌ای است) |
| ظاهر/ترتیب ردیف‌ها | `Templates/Layouts/` — `PerWaybillRecords` (هر بارنامه یک ردیف)، `PerGroupRecords` (`group_by`)، `SummaryRecords` (خلاصه) |
| عنوان، خط بازه، ردیف جمع | `TemplateDocumentBuilder` |
| API و اعتبارسنجی | `FrequentReportController`، `StoreFrequentReportExportRequest` |
| صف، سوکت، فایل، حذف | مشترک با گزارش‌ساز: `ReportExportService` ← `GenerateReportExport` ← `ReportExportGenerator` |
