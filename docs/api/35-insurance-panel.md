# پنل بیمه

[← فهرست بخش‌ها](README.md)

**پنل:** پنل بیمه (جدا از پنل شرکت و ادمین) — **تعداد روت:** ۳

پنل کاربران شرکت‌های بیمه: کاربرانِ نماینده کشوری، نماینده استانی یا نمایندگیِ یک شرکت بیمه ([بخش ۳۴](34-insurance-agencies.md)). کاربر شرکت‌هایی را می‌بیند که **قرارداد بیمه** در محدودهٔ نماینده‌اش دارند و فقط
بارنامه‌هایی را که با همین قراردادها بیمه شده‌اند. روت‌ها زیر `/api/insurance` هستند و نام روت‌ها با `insurance.` شروع می‌شود.
این پنل فقط **خواندنی** است (لیست شرکت‌ها، لیست بارنامه‌ها، جزئیات بارنامه).

### ۳۵.۱ نقش و کاربر

- نقش جدید: **`insurance`** («نمایندگی بیمه»). در دیپلوی با `InsuranceRoleSeeder` ساخته می‌شود و مجوزهایش (`insurance.*`) با `php artisan generate-permissions` به آن و کاربرانش داده می‌شود.
- کاربر این نقش **شرکت ندارد** (`company_id` خالی است؛ ارسال `company_id` در ساخت، `422` می‌دهد).
- ادمین کاربر را با `POST /api/admin/users` می‌سازد ([بخش ۲۱](21-admin-users.md)). وقتی `role_id` نقش `insurance` باشد فقط این فیلد **الزامی** می‌شود، و برای هر نقش دیگر **پذیرفته نمی‌شود** (`422`؛ در ویرایش با عوض‌شدن نقش، خالی می‌شود):

| فیلد                  | قاعده                                                                         |
|-----------------------|-------------------------------------------------------------------------------|
| `insurance_agency_id`! | شناسهٔ نماینده بیمهٔ موجود و حذف‌نشده از هر سطح (کشوری، استانی، نمایندگی)؛ انتخاب از لیست درختی ([بخش ۳۴](34-insurance-agencies.md)) |

شرکت بیمه، استان، شهر و سطح دید، اطلاعات **خودِ نماینده** هستند (`insurance_company_id`، `state_code`، `city_code`، `level`) و کاربر فقط به نماینده وصل است؛
با جابه‌جا شدن نمایندگی زیر استان دیگر، دسترسی کاربرانِ آن استان‌ها هم عوض می‌شود. نماینده‌های کشوری و استانیِ تازه‌ساخته (خالی) هم کاربر می‌گیرند و ورودشان کار می‌کند. `insurance_agency_id` در خروجی کاربر (`UserResource`) هم می‌آید (برای کاربران دیگر `null`).

### ۳۵.۲ ورود و نشست بیمه (مهم برای فرانت)

ورود همان `POST /api/auth/login` است ([بخش ۳](03-auth.md)). سرور وقتی کاربر نقش `insurance` دارد، **توکن مخصوص پنل بیمه** (ability: `insurance-user`) می‌سازد و
اطلاعات نمایندگی/سطح را در `insurance_access` برمی‌گرداند:

```json
{
  "token": "15|plain-text-token",
  "user": { "id": 31, "company_id": null, "insurance_agency_id": 5, "full_name": "..." },
  "role": { "id": 6, "name": "insurance", "display_name": "نمایندگی بیمه" },
  "permissions": ["insurance.companies.index", "insurance.companies.waybills.index", "insurance.companies.waybills.show", "profile.show", "profile.update"],
  "auth_mode": "insurance",
  "insurance_access": {
    "access_type": "insurance_user",
    "level": "province",
    "level_label": "استانی",
    "insurance_company": { "id": 3, "name": "پارسیان" },
    "agency": { "id": 14, "parent_id": 13, "title": "سرپرستی استان تهران", "code": null, "level": "province", "...": "InsuranceAgencyResource" },
    "city": null,
    "state": { "id": 1, "code": 11, "name": "تهران" },
    "issued_by": { "id": 31, "full_name": "..." },
    "permissions": ["insurance.companies.index", "insurance.companies.waybills.index", "insurance.companies.waybills.show", "profile.show", "profile.update"],
    "expires_at": null
  }
}
```

- **تشخیص پنل:** `auth_mode === "insurance"` (ورود خود کاربر) یا `"insurance_support"` (ادمین داخل پنل یک نمایندگی، [بخش ۳۴.۸](34-insurance-agencies.md)) → پنل بیمه.
  دیگر لازم نیست `role.name` را برای تشخیص پنل بررسی کنید (کاربر بیمه دیگر `system` نیست).
- `insurance_access.level` / `level_label`: سطح نمایندگیِ کاربر (کشوری، استانی، نمایندگی) برای نمایش در هدر؛ `agency`: نماینده کاربر (برای نام، `agency.title` را نشان دهید که برای نماینده خالی هم پر است)؛ `state`: استانِ نماینده استانی/نمایندگی (برای کشوری از شهر دفترش، وگرنه `null`)؛ `city`: شهر دفتر نماینده یا `null` اگر هنوز پر نشده؛ `insurance_company`: شرکت بیمهٔ نماینده. محدودیت دسترسی را سرور اعمال می‌کند.
- `GET /api/auth/checkToken` با توکن بیمه همین ساختار (بدون `token`) را برمی‌گرداند؛ `POST /api/auth/logout` فقط همان توکن را باطل می‌کند.
- مجوزهای این کاربر `insurance.*` است (به‌علاوهٔ `profile.show` و `profile.update` که از قالب نقش می‌آیند ولی برای او کار نمی‌کنند). هر روت `/api/admin/*` برایش `403` می‌دهد.
- `/api/user/*` (پنل شرکت) برای این کاربر `403` است چون شرکت ندارد؛ از جمله **`/api/user/profile` (ویرایش پروفایل) برای کاربر بیمه کار نمی‌کند** و صفحهٔ پروفایل را در پنل بیمه نسازید، حتی اگر `profile.*` در `permissions` باشد (ویرایش اطلاعات او کار ادمین است، [بخش ۲۱](21-admin-users.md)).
- توکن‌های قدیمی کاربران بیمه (قبل از این تغییر) هم با `checkToken` به `auth_mode: "insurance"` تبدیل می‌شوند؛ نیازی به ورود دوباره نیست.

**ورود ادمین به پنل یک نمایندگی** (`insurance_support`): ادمین از [بخش ۳۴.۸](34-insurance-agencies.md) یک توکن موقت (۱ روز) می‌گیرد. در این نشست:
- `insurance_access.access_type = "support"` و `agency` همان نمایندگی است (`level` سطح همان نمایندگی است)؛ `role` نقش `insurance` و `permissions` فقط مجوزهای `insurance.*` است؛
- فقط `/api/insurance/*` با محدودهٔ همان نمایندگی کار می‌کند؛ هر مسیر دیگر (حتی ادمین) `403` است؛
- اگر نمایندگی بعداً حذف شود، روت‌های پنل `404` («نمایندگی بیمه یافت نشد») می‌دهند.

### ۳۵.۳ سطح دسترسی

سطح (`level`)، شرکت بیمه (`insurance_company_id`) و جایگاه در درخت (`parent_id`) از **نمایندهٔ کاربر** خوانده می‌شوند، نه از خود کاربر.

| سطح        | چه بارنامه‌هایی را می‌بیند                                                                                                                       |
|------------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| `country`  | همهٔ بارنامه‌هایی که با قرارداد بیمه‌ای از **شرکت بیمهٔ خودش** بیمه شده‌اند، حتی اگر نمایندگی دیگری ثبتشان کرده (و قراردادهای بدون نمایندگی)        |
| `province` | بارنامه‌های بیمه‌شده با قراردادهای **خودِ نماینده استانی و نمایندگی‌های زیرش** (`parent_id` = نماینده استانی)                                       |
| `agency`   | فقط بارنامه‌های بیمه‌شده با قراردادهای **نمایندگی خودش** (نمایندگی‌ای که کاربر به آن وصل است)                                                            |

قواعد مشترک:
- بارنامهٔ شرکت بیمهٔ دیگر هرگز دیده نمی‌شود.
- شرکتی که ادمین اتصالش را به نمایندگی قطع کرده ([بخش ۳۴](34-insurance-agencies.md)) و بارنامه‌هایش دیده نمی‌شوند.
- شرکتی که برای کاربر هیچ قراردادی در محدوده‌اش ندارد، `404` می‌دهد (وجود شرکت لو نمی‌رود).
- کاربری که کاربر پنل بیمه نیست (ادمین، کاربر شرکت، یا کاربر نقش بیمه‌ای که به نمایندگی وصل نیست یا نمایندگی‌اش حذف شده) روی این روت‌ها `403` می‌گیرد.
- فقط بارنامه‌هایی دیده می‌شوند که فیلد «بیمهٔ مسئولیت» (`liability_insurance`) آن‌ها یکی از قراردادهای مجاز کاربر است؛ بارنامه‌ای که بیمه ندارد یا با قرارداد دیگری بیمه شده، در لیست نمی‌آید و جزئیاتش `404` است.

### ۳۵.۴ روت‌ها و مجوزها

| #    | متد | مسیر                                                         | نوع ورودی    | مجوز لازم                            | کاربرد                                   |
|------|-----|--------------------------------------------------------------|--------------|--------------------------------------|------------------------------------------|
| ۳۵.۱ | GET | `/api/insurance/companies`                                   | query string | `insurance.companies.index`          | شرکت‌های دارای قرارداد در محدودهٔ کاربر    |
| ۳۵.۲ | GET | `/api/insurance/companies/{company}/waybills`                | query string | `insurance.companies.waybills.index` | بارنامه‌های بیمه‌شدهٔ یک شرکت            |
| ۳۵.۳ | GET | `/api/insurance/companies/{company}/waybills/{waybill}`      | ندارد        | `insurance.companies.waybills.show`  | جزئیات یک بارنامهٔ بیمه‌شده              |

`{company}` شناسهٔ شرکت (`id` از روت اول) و `{waybill}` شناسهٔ بارنامه است؛ هر دو فقط عدد.

### ۳۵.۵ خروجی‌ها

**`GET /api/insurance/companies`** — لیست شرکت‌ها، مرتب بر اساس نام (با دستور مشترک لیست: `paginate`، `search`، ...):

```json
{
  "success": true,
  "message": "...",
  "data": [
    { "id": 12, "name": "شرکت نمونه", "organization_code": "2488955", "city_code": 1101, "tel": "37776729", "insurances_count": 2 }
  ]
}
```

با `paginate=1&itemsPerPage=20&page=1` شیء paginator ([بخش ۱](01-general-conventions.md)) برمی‌گردد و ردیف‌ها در `data.data` هستند. `search` روی نام و کدهای شرکت کار می‌کند.
`insurances_count`: تعداد قراردادهای آن شرکت که در محدودهٔ کاربر است.

**`GET /api/insurance/companies/{company}/waybills`** و **`.../{waybill}`** — بارنامه‌ها با **همان شکل خروجی بارنامهٔ پنل شرکت** ([بخش ۱۹](19-waybills.md))،
فقط بارنامه‌هایی که `liability_insurance` آن‌ها یکی از قراردادهای مجاز کاربر است. لیست از دستور مشترک (`paginate`، `search`، `eq-...`، `min-...` و ...) پیروی می‌کند؛
مثلاً `GET /api/insurance/companies/12/waybills?paginate=1&itemsPerPage=20&eq-status=completed&min-issued_at=2026-10-01`.
بارنامه‌ای که با قرارداد خارج از محدودهٔ کاربر بیمه شده `404` می‌دهد.

> توجه: این خروجی همهٔ ستون‌های بارنامه (از جمله مبالغ) را دارد. اگر بیمه‌گر نباید بعضی را ببیند، ستون‌های قابل نمایش در پنل بیمه باید محدود شود (در حال حاضر محدود نشده است).

### ۳۵.۶ خطاها

| وضعیت | چه زمانی                                                                           | بدنه                                                                  |
|-------|------------------------------------------------------------------------------------|-----------------------------------------------------------------------|
| `401` | توکن نامعتبر/منقضی                                                                 | `{ message }`                                                         |
| `403` | کاربر بیمه نیست؛ یا به هیچ نمایندگی (حذف‌نشده‌ای) وصل نیست؛ یا مجوز روت را ندارد | `{ success:false, message, errors }` یا `{ message }`                 |
| `404` | شرکت در محدودهٔ کاربر قرارداد ندارد، یا بارنامه با قرارداد مجاز بیمه نشده / وجود ندارد | `{ success:false, message, errors: { error: ["..."] } }`              |

### ۳۵.۷ پیشنهاد صفحه‌ها در UI

1. **داشبورد/لیست شرکت‌ها** (`insurance/companies`): جدول شرکت‌ها (نام، کد سازمان، شهر، تلفن، تعداد قراردادها) با جست‌وجو و صفحه‌بندی.
2. **بارنامه‌های یک شرکت** (`insurance/companies/:id/waybills`): همان جدول و فیلترهای بارنامه در پنل شرکت (فقط خواندنی)، بدون دکمه‌های ایجاد/ویرایش/حذف/ابطال.
3. **جزئیات بارنامه**: نمایش فقط‌خواندنی؛ بخش‌های مالی را در صورت تصمیم کسب‌وکار پنهان کنید (پاسخ سرور همه را می‌فرستد).
4. منوی پنل بیمه را با `permissions` بسازید (`insurance.companies.index` و ...) و `403/404` را با پیام سرور نشان دهید.
